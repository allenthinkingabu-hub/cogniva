## 零、 模块定位与决策拓扑 (Module Positioning & Topology)

系统 2 是 L1 LLMOps 网关的**“流量决策大脑与容灾控制中枢”**。它紧承系统 3 缓存穿透检查之后，负责为每一个进入实质推理阶段的 LLM 请求挑选最合理的物理端点（Provider Endpoint）：
* **动态多维打分**：基于“滑动窗口首字时间（P95 TTFT）+ Token 成本权重 + 错误率”实施多目标动态打分；
* **消灭长尾延迟**：主选端点在 1500ms 内未出字时，激活**对冲双发（Hedged Requests）**，首字竞速胜出；
* **秒级故障自愈**：出现连续 429 或 5xx 时，在 **$\le 200\text{ms}$** 内完成断路器跳闸并触发三阶优雅降级。

## 一、 无锁滑动时间轮数据结构 (Lock-Free Sliding Time-Wheel)

为了在高并发下以极低开销统计每个端点的 P95 TTFT 与错误率，采用基于连续内存的无锁环形数组（RingBuffer Bucket）：

```mermaid
classDiagram
    class SlidingWindowMetrics {
        -int windowSizeSeconds = 60
        -AtomicReferenceArray~MetricBucket~ ringBuffer
        +recordSuccess(long ttftNs, long durationNs)
        +recordFailure(ErrorCode code)
        +getSnapshot() MetricsSnapshot
    }

    class MetricBucket {
        -long epochSecond
        -LongAdder requestCount
        -LongAdder failureCount
        -LongAdder rateLimit429Count
        -ConcurrentHistogram ttftHistogram
    }

    class MetricsSnapshot {
        +double p50TtftMs
        +double p90TtftMs
        +double p95TtftMs
        +double p99TtftMs
        +double failureRate
        +long inFlightCount
    }

    SlidingWindowMetrics o-- MetricBucket
    SlidingWindowMetrics ..> MetricsSnapshot : generates
```

### 环形时间轮物理更新算法：
1. **当前秒索引定位**：$\text{index} = (\text{CurrentEpochSecond}) \pmod{60}$；
2. **过期桶原子清空（CAS）**：若读取桶的 `epochSecond` 不等于当前物理秒，利用 CAS 操作将 `MetricBucket` 内的 `LongAdder` 与直方图重置为当前秒；
3. **读写性能**：打点与采样全程无全局互斥锁，时空复杂度恒定为 $O(1)$，对主数据面附加延迟 $\le 0.05\text{ms}$。

## 二、 多目标动态打分数学模型与 Full Jitter 防共振公式

### 1. 综合评价值打分方程
为候选端点集合中的每个物理节点 $i$ 计算综合代价得分 $S_i$（分值越小越优）：

$$S_i = w_{\text{lat}} \cdot \left(\frac{\text{TTFT}_{\text{P95}}(i)}{\text{BaseLatency}}\right) + w_{\text{cost}} \cdot \left(\frac{\text{TokenCost}(i)}{\text{BaseCost}}\right) + w_{\text{err}} \cdot \left(\frac{\text{ErrorCount}_{60\text{s}}(i)}{\text{TotalCount}_{60\text{s}}(i) + 1}\right) + w_{\text{in}} \cdot \left(\frac{\text{InFlight}(i)}{\text{MaxCapacity}(i)}\right)$$

* **权重归一化约束**：$w_{\text{lat}} + w_{\text{cost}} + w_{\text{err}} + w_{\text{in}} = 1.0$（可通过配置中心热调整）；
* **基准常数**：$\text{BaseLatency} = 1000\text{ms}$，$\text{BaseCost} = \$0.002 / 1\text{K tokens}$。

### 2. Full Jitter 指数退避加随机抖动公式
在触发重试或对冲调度时，为了避免集群几千个长连接在同一微秒发起重试造成“自制流量雪崩（Thundering Herd）”，引入 Full Jitter 随机打散：

$$T_{\text{sleep}} = \text{random}\left(0, \ \min\left(T_{\text{max}}, \ T_{\text{base}} \cdot 2^{\text{attempt}}\right)\right)$$

## 三、 1500ms 对冲双发首字竞速全链路时序图 (Hedged Request Racing)

```mermaid

    participant Primary as 主选端点 (Primary EP)
    participant Hedged as 备选端点 (Hedged EP)
    participant Pipe as 下游数据管道 (Sys 4)

    Router->>Primary: 1. 向上游主端点发起 HTTP/2 调用
    Router->>Scheduler: 2. 注册 1500ms 单次定时器 (TimerCondition=Primary)
    
    alt 场景 A: 主端点在 1500ms 内正常返回 (正常路径)
        Primary-->>Router: 首个 Chunk 到达 (TTFT = 850ms)
        Router->>Scheduler: 判定 Primary 胜出，注销 1500ms 定时器
        Router-->>Pipe: 将 Primary 数据流绑定至下游
    else 场景 B: 主端点发生长尾卡顿 (超时 1500ms 未吐字)
        Scheduler-->>Router: 1500ms 定时器到期触发 (Timer Expired)
        Router->>Hedged: 立即向备选端点发起完全相同的请求
        
        par 双路首字竞速 (First-Token Racing)
            Primary-->>Router: 主端点继续挂起中...
        and
            Hedged-->>Router: 备用节点首包率先到达！(TTFT = 250ms)
        end
        
        Router->>Primary: 3. 立即下发 HTTP/2 RST_STREAM (终止主节点算力)
        Router-->>Pipe: 4. 将 Hedged 节点数据流无缝对接至下游
        Router->>Router: 5. 记录指标: hedged_requests_total{result="win_hedged"}
    end
```

## 四、 断路器三态状态机转移矩阵 (Circuit Breaker State Machine)

```mermaid
stateDiagram-v2
    [*] --> CLOSED: 初始健康态 (放行 100% 流量)

    CLOSED --> OPEN: 触发熔断阈值\n(错误率 >= 25% 或 连续触发 3 次 429)
    
    state OPEN {
        [*] --> InCooling: 立即将节点从候选池剔除\n后续流量走降级路由
        InCooling --> HalfOpenReady: 保持 OPEN 状态 30 秒 (WaitDuration)
    }

    OPEN --> HALF_OPEN: 冷却倒计时归零，转入半开态

    state HALF_OPEN {
        [*] --> Probing: 仅放行 1% 真实探测流量\n并发探活请求严格限制在 5 笔以内
    }

    HALF_OPEN --> CLOSED: 连续 5 笔探活请求均成功 (HTTP 200 且 TTFT <= 1500ms)
    HALF_OPEN --> OPEN: 探活中发生任何 1 笔 5xx / 429\n(重新熔断，冷却时间延长至 60s)

    CLOSED --> DISABLED: SRE 手动隔离节点
    OPEN --> DISABLED: SRE 手动隔离节点
    DISABLED --> [*]
```

### 供应商 429 自适应退避机制（Adaptive Backoff）：
若上游明确返回 `Retry-After: N` 响应头，状态机强制将冷却时间设定为：
$$\text{ActualCoolDown} = \max\left(N, \ 30\text{s}\right)$$
严禁在冷却期未满时盲目向该端点注入探活流量。

## 五、 三阶优雅降级决策树 (Fallback Cascading Ladder)

```mermaid
    Tier1Check -->|"OPEN"| Tier2Check{"性价比平替 (如 DeepSeek-V3) 状态?"}
    
    Tier2Check -->|"CLOSED"| CallTier2["【第 2 阶降级】降级至低成本高吞吐模型\n(参数适配，注入 X-Fallback: Tier2)"]
    
    Tier2Check -->|"全灭 OPEN"| Tier3Fallback["【第 3 阶保底】触发网关兜底降级策略"]
    
    Tier3Fallback --> RuleA["策略 A: 转向私有化部署 vLLM 开源兜底集群"]
    Tier3Fallback --> RuleB["策略 B: 输出预置友好话术 (维持会话不崩溃)"]
```
