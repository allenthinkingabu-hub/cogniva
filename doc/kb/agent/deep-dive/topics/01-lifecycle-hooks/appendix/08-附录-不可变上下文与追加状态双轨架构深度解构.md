## 零、 核心认知澄清：两大街区的物理边界

在企业级 AI Agent 的受控宿主运行时（Harness）中，系统把数据严格隔离在**两个物理性质完全相反的街区**：

```
                    【一次 Agent 执行过程中的两大街区】
                                    │
       ┌────────────────────────────┴────────────────────────────┐
       ▼                                                         ▼
【街区一：不可变执行上下文 (FrozenRunContext)】          【街区二：仅追加状态账本 (Append-Only RunState)】
  * 物理性质：100% 只读冻结，绝无任何可变字段             * 物理性质：微观密封不可改，宏观单调仅追加 (Append-Only)
  * 数据来源：功能六策略快照 + 功能七物理/链路指纹         * 数据来源：各步骤思维链推导、工具调用返回值、审批回执
  * 核心使命：杜绝串号踩踏，确立全局合法契约               * 核心使命：事件溯源 (Event Sourcing)，支撑审计与回放
  * 生命历程：进门生成，全程不变，单向透传                 * 生命历程：一步一条事件，只增不减，动态投影最新状态
```

* **彻底打消歧义**：
  1. **`FrozenRunContext`（不可变上下文）**：内部**没有任何可变字段**，它是 **100% 锁死** 的！它里面装的正是**功能六的策略快照** + **功能七的环境指纹与 TraceID**；
  2. **那什么是会随着运行而增加的？**：在执行过程中随着每一步（Step）不断推进的**业务动态历史**（比如：多模态质检的评分、大模型最新的思考内容、调 Stripe 产生的流水号），那个东西叫 **`RunState`（运行状态账本）**，它和 Context 是**两个相互独立的物理对象**！

## 一、 完整的不可变上下文数据结构（`FrozenRunContext`）

以下是生产级 L2 Harness 微内核中，由**功能六**和**功能七**共同装配完成的**完整只读上下文数据结构**（采用 Python Pydantic v2 严格强类型实现）：

```python
from datetime import datetime, timezone
from typing import List, Dict, Optional
from pydantic import BaseModel, Field, ConfigDict


# ==============================================================================
# 子模块 A：功能六塞入的“业务决策与风控策略快照”（来自配置中心，只读锁死）
# ==============================================================================
class ModelPolicySnapshot(BaseModel):
    """大模型与算力策略快照"""
    model_config = ConfigDict(frozen=True)  # 严格只读

    model_id: str = Field(description="锁死模型ID，如 claude-3-5-sonnet@20241022")
    temperature: float = Field(default=0.0, description="锁死推理温度，杜绝随机漂移")
    seed: int = Field(default=42, description="随机种子，保证确定性可复现回放")
    max_tokens_per_step: int = Field(default=4096, description="单步最大输出 Token 限额")


class RiskPolicySnapshot(BaseModel):
    """风控与资金退赔红线策略快照"""
    model_config = ConfigDict(frozen=True)  # 严格只读

    max_auto_refund_limit: float = Field(description="自动仅退款上限，例如 50.00 美元")
    reverse_shipping_threshold: float = Field(description="逆向运费触发弃件阈值，例如 35.00 美元")
    require_human_approval_above: float = Field(description="必须切入人机协同审批的金额红线，例如 50.00 美元")


class DecisionPolicySnapshot(BaseModel):
    """【功能六产出】完整的商户决策策略快照大集合"""
    model_config = ConfigDict(frozen=True)

    config_snapshot_hash: str = Field(description="整套策略的 SHA-256 指纹，用于事后审计对账")
    prompt_template_version: str = Field(description="提示词模板版本号，如 prompt:dispute:v2.4.1")
    model_policy: ModelPolicySnapshot
    risk_policy: RiskPolicySnapshot
    tool_whitelist: List[str] = Field(description="允许调用的工具白名单：['multimodal_inspect', 'stripe_refund']")
    tool_whitelist_hash: str = Field(description="工具白名单签名摘要")


# ==============================================================================
# 子模块 B：功能七塞入的“分布式链路追踪”（来自 W3C Header / 网络总线，只读锁死）
# ==============================================================================
class DistributedTracingContext(BaseModel):
    """【功能七产出 1】分布式全链路可观测性指纹"""
    model_config = ConfigDict(frozen=True)

    traceparent: str = Field(description="符合 W3C 规范的透传头: 00-4bf92f35...-01")
    trace_id: str = Field(description="全局唯一 TraceID，串联跨微服务所有日志与指标")
    root_span_id: str = Field(description="根 SpanID，代表本次 Agent Run 的物理起点")
    sampled: bool = Field(default=True, description="是否被全链路采样收集")


# ==============================================================================
# 子模块 C：功能七塞入的“物理宿主环境指纹”（来自 Linux 容器与 K8s 节点，只读锁死）
# ==============================================================================
class HostPhysicalFingerprint(BaseModel):
    """【功能七产出 2】当前正在执行任务的物理节点身份凭证"""
    model_config = ConfigDict(frozen=True)

    worker_pod_ip: str = Field(description="当前 Worker 容器的 Pod IP，如 10.244.5.88")
    k8s_node_name: str = Field(description="宿主机物理节点名，如 node-us-east-zone2-c4")
    harness_version: str = Field(description="Harness 微内核引擎版本，如 v1.4.2")
    git_commit_sha: str = Field(description="当前 Pod 运行的代码版本哈希，如 c554647")


# ==============================================================================
# ★★★ 终极总装：完整的不可变执行上下文（FrozenRunContext）★★★
# ==============================================================================
class FrozenRunContext(BaseModel):
    """
    【Hook 1 流水线最终成果】不可变执行上下文
    在 on_run_load 的末尾整体过塑锁死（frozen=True）
    下游 Hook 2~9 只能“只读访问”，没有任何人能改动其中任何一个字段！
    """
    model_config = ConfigDict(frozen=True)  # ★★★ 全局强制不可变硬锁！★★★

    # 1. 业务逻辑唯一身份
    run_id: str = Field(description="本次 Agent Run 的全局唯一业务流水号，如 run_01jb94xkq7")
    tenant_id: str = Field(description="商户/租户唯一标识，如 STORE_US_01")
    dispute_id: str = Field(description="电商售后争议工单号，如 DISPUTE-2025-9981")
    buyer_id: str = Field(description="买家身份标识，如 buyer_us_8821")
    created_at: datetime = Field(default_factory=lambda: datetime.now(timezone.utc), description="任务准入加载时间戳")

    # 2. 功能六塞进来的业务策略（灵魂法则）
    policy: DecisionPolicySnapshot

    # 3. 功能七塞进来的分布式链路与物理指纹（身体与网络身份）
    tracing: DistributedTracingContext
    host: HostPhysicalFingerprint
```

## 三、 深度辩证：为什么动态状态（State）在物理上也必须是“Append-Only（仅追加）”？

在传统平庸的 Agent 框架中，程序员习惯在内存里原地覆写状态（In-place Mutation）：
```python
# 致命坏味道：原地覆盖，历史被黑板擦抹除！
run_state.current_tool_result = {"status": "SUCCESS"}
run_state.current_tool_result = {"status": "FAILED"} # 前一次状态丢失！
```

### 1. 覆写是原罪，追加才是真理（Append-Only Paradigm）
在企业级金融与合规场景中，**原地覆写是灾难的根源**：
* 状态一旦被覆盖，模型在 Step 1 到底看到了什么、做出了什么推理，全部死无对证；
* 事后对账与司法审计无法取证；
* 备用节点故障接管时无法得知外部副作用是否已经发生。

**真正的企业级设计：借鉴银行账务流水（Bank Ledger）与事件溯源（Event Sourcing）**：
* 银行绝不会在数据库里把你的余额直接改写，而是追加记录一条 `+100` 或 `-50` 的流水；
* 当前余额只是所有不可变流水累加计算出的**最新投影（Materialized View）**；
* Agent 执行中的思维链、工具调用与审批回执，**每一个 Step 都是一条已经封口的独立事件，生成就绝不能改，只能往后单调追加！**

### 2. 仅追加事件账本的数据结构实现

```python
class StepEvent(BaseModel):
    """单步执行事件记录：一旦写入，永久封存，严格只读！"""
    model_config = ConfigDict(frozen=True)  # ★ 单条事件绝对不可变！

    step_index: int = Field(description="执行步数序号：1, 2, 3...")
    fencing_token: int = Field(description="落盘递增防御版本号")
    action_type: str = Field(description="动作类型：THOUGHT / TOOL_CALL / HITL_APPROVAL")
    payload: Dict[str, any] = Field(description="动作参数与返回值快照")
    executed_at: datetime = Field(default_factory=lambda: datetime.now(timezone.utc))
    event_hash: str = Field(description="基于前序事件哈希计算的链式校验码 (Merkle Hash)")


class AppendOnlyRunState(BaseModel):
    """
    【宏观状态机】基于事件溯源的仅追加账本
    状态的推进只能通过 append_event() 进行，严禁原地篡改旧事件！
    """
    run_id: str
    current_status: str = "INITIALIZED"
    event_stream: List[StepEvent] = []  # ★ 核心账本：只能 append，不能修改已有元素！

    def append_event(self, event: StepEvent) -> None:
        """只允许单调追加事件"""
        self.event_stream.append(event)
        self.current_status = event.payload.get("next_status", self.current_status)

    @property
    def current_step(self) -> int:
        """当前步数：由账本长度自动计算得出"""
        return len(self.event_stream)

    @property
    def committed_tool_refs(self) -> List[str]:
        """已提交且产生物理副作用的幂等键列表（用于故障恢复防重放）"""
        return [
            e.payload["operation_ref"] 
            for e in self.event_stream 
            if e.action_type == "TOOL_CALL" and e.payload.get("status") == "SUCCESS"
        ]
```

## 四、 双轨架构带来的三大降维打击优势

```
┌────────────────────────────────────────────────────────┐
│  FrozenRunContext (不可变执行上下文)                   │
│  - 契约基因，跨网络透传，绝无脏写                      │
└──────────────────────────┬─────────────────────────────┘
                           │ 驱动
                           ▼
┌────────────────────────────────────────────────────────┐
│  AppendOnlyRunState (仅追加状态账本)                   │
│  - 事件溯源，只增不改，可计算当前投影                  │
└────────────────────────────────────────────────────────┘
```

1. **防赖账与法律级存证（Cryptographic Audit Trail）**：  
   月末商户质疑“为什么直接给我手表争议工单仅退款 $50”，系统直接调出不可变的 Context 策略版本与 Append-Only 事件流水链。每一条记录均带哈希签名，消灭任何人为篡改和抵赖空间。
2. **时间旅行调试（Time-Travel Replay & Sandbox Playback）**：  
   线上出现诡异决策时，研发不需要盲猜。沙箱可以直接读取 `event_stream` 的前两条事件，精确复原出 Agent 在做出错误决定前那一毫秒的**所有心智截面与内存镜像**。
3. **节点故障接管的绝对幂等（Zero Double-Spend）**：  
   当 Worker 在打款瞬间断电，备用节点通过反序列化 Append-Only 账本，能一秒识别出 `stripe_refund` 是否已在 `committed_tool_refs` 中，杜绝因节点宕机发生重复退款资损。
