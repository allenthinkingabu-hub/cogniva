## 第一章：基于 ASD-STE100 规范的数据主权与跨境物理熔断工程技术标准

本章节遵循国际工业与航空标准 **ASD-STE100（Simplified Technical English）** 编写。旨在通过严格受控词汇、短句结构（$\le 20$ 词）与主动语态，消除跨国开发、安全审计与法律合规团队的技术理解歧义。

### SECTION 1: PURPOSE AND DEFINITIONS / 目的与术语定义

#### STE English:
1. This section gives mandatory rules for data sovereignty and cross-border circuit breakers in Hook 2.
2. **Data Sovereignty**: The legal principle that data is subject to the laws of the country where it is collected.
3. **Cross-Border Transfer**: The network transmission of personal data from one country to a server in a different country.
4. **Physical Circuit Breaker**: A software control that terminates outbound network connections immediately when rules are broken.
5. **Standard Contractual Clauses (SCC)**: Legal contract templates approved by the European Commission for cross-border data export.
6. **Sovereign Fallback**: The automatic rerouting of an inference task to a local model inside the legal jurisdiction.
7. **Post-Sales Agent**: An AI system that resolves e-commerce customer disputes, refunds, and replacements.

#### 标准中文对照：
1. 本章节给出 Hook 2 中数据主权与跨境物理熔断门禁的强制性规则。
2. **数据主权（Data Sovereignty）**：数据受其收集所在国法律管辖的法律原则。
3. **跨境传输（Cross-Border Transfer）**：个人数据从一国通过网络传输至另一国服务器的过程。
4. **物理熔断（Physical Circuit Breaker）**：当违反安全规则时，立即终止出网网络连接的底层软件控制机制。
5. **标准合同条款（SCC）**：由欧盟委员会批准用于跨国数据出境的法定合同模板。
6. **主权降级（Sovereign Fallback）**：将推理任务自动重定向至法定管辖区内本地模型的自愈机制。
7. **售后决策 Agent（Post-Sales Agent）**：负责调解电商客户争议、退款与补发配件的 AI 系统。

### SECTION 2: OPERATIONAL INVARIANTS FOR CROSS-BORDER ROUTING / 跨境路由操作不变量

#### STE English:
1. The harness must evaluate data sovereignty before it opens a network connection to any AI model.
2. If data originates in the European Union, the engine must identify European tax IDs and invoice records.
3. The engine must check the physical country location of the target model server.
4. If the model server is outside the European Union, the engine must verify an active SCC agreement.
5. If the tenant does not have a valid SCC agreement, the harness must trigger the physical circuit breaker.
6. When the physical circuit breaker triggers, the harness must close the TCP socket immediately.
7. The harness must throw a `DataSovereigntyViolationException` and log a high-priority compliance event.
8. The harness must immediately route the prompt to an open-weights model hosted inside Frankfurt.
9. Do not bypass the sovereignty barrier for performance optimization or model capability preferences.
10. Do not send unmasked customer invoices across legal borders without legal documentation.

#### 标准中文对照：
1. 宿主系统在向任何 AI 模型建立网络连接前，必须先评估数据主权合规性。
2. 若数据产生于欧盟，引擎必须识别其中的欧洲税务识别号与发票记录。
3. 引擎必须检查目标模型服务器的物理归属国。
4. 若模型服务器位于欧盟境外，引擎必须核实是否存在生效的 SCC 协议。
5. 若商户租户未持有合法有效的 SCC 协议，宿主系统必须触发物理熔断。
6. 当物理熔断触发时，宿主系统必须立即关闭底层 TCP 套接字。
7. 宿主系统必须抛出 `DataSovereigntyViolationException` 并记录高优先级合规审计事件。
8. 宿主系统必须立即将 Prompt 重定向至部署在法兰克福境内的开源权重模型。
9. 严禁为了追求推理性能或高级模型能力而绕过数据主权门禁。
10. 严禁在没有法定出境文件的情况下将未掩码的客户发票跨境传输。

### SECTION 3: STEP-BY-STEP PROCEDURE / 逐步操作规程

```
[Context Ready] ──> [Detect Region & Invoice] ──> [Inspect Model Endpoint] ──> [Verify SCC/DPF] ──> [Pass OR Hard Cut & Local Fallback]
```

#### STE English:
1. **Step 1 (Inspection)**: Read the dispute prompt, buyer country code, and tax document identifiers.
2. **Step 2 (Endpoint Resolution)**: Resolve the IP address of the target model API to identify its physical country.
3. **Step 3 (Comparison)**: Compare the buyer jurisdiction against the model server physical location.
4. **Step 4 (Legal Verification)**: If the transfer is cross-border, check the tenant legal agreement registry for valid SCCs.
5. **Step 5 (Decision Branch)**:
   * **Branch A (Allowed)**: If valid SCCs exist, attach compliance audit metadata and send the request.
   * **Branch B (Blocked)**: If no valid SCC exists, trip the circuit breaker and abort outbound network I/O.
6. **Step 6 (Fallback Execution)**: Reconfigure the client transport to the local Frankfurt GPU cluster.
7. **Step 7 (Completion)**: Execute inference on the local model and deliver the dispute arbitration result.

#### 标准中文对照：
1. **步骤 1（上下文审查）**：读取争议 Prompt、买家国别代码以及税务发票标识符。
2. **步骤 2（目标端点解析）**：解析目标模型 API 的 IP 地址以识别其物理服务器所在国。
3. **步骤 3（管辖区比对）**：比对买家法律管辖区与模型服务器物理归属地。
4. **步骤 4（法定凭证核验）**：若属于跨境传输，查询商户法务协议注册表以验证合法 SCC。
5. **步骤 5（决策分支）**：
   * **分支 A（准入放行）**：若存在有效 SCC，附加合规审计元数据并发送请求。
   * **分支 B（物理熔断）**：若无有效 SCC，触发熔断器并彻底中止出网 I/O。
6. **步骤 6（主权降级执行）**：将底层传输客户端重定向至法兰克福本地自建 GPU 集群。
7. **步骤 7（完成闭环）**：在本地模型上完成推理并交付争议仲裁决策。

## 第二章：核心概念深度通俗拆解（结合电商售后退赔）

在跨国电商业务中，数据安全绝不仅仅是“加解密”那么简单，而是直接与**国际地缘政治、长臂管辖法律与主权机房**深度捆绑。

### 1. 什么是“数据主权”（Data Sovereignty / Data Residency）？
* **大白话定义**：**“哪国公民产生的数据，就必须受哪国法律管辖，原则上‘人身和数据’都不得随意离开其国境！”**
* **在售后退赔 Agent 中的具象表现**：  
  法国买家 Alice 购买了 $180 的手表，发生表盘划痕纠纷。Alice 上传了巴黎开具的增值税发票（含法国法定企业税号 Numéro Fiscal）、带巴黎 GPS EXIF 坐标的破损照片、以及法语投诉文本。  
  依据欧盟 **GDPR 第五章**（数据的国际传输规则）以及欧洲法院里程碑式的 **“Schrems II 判决”**：**欧盟公民的数据具有法定本土驻留权，原则上必须留存在欧洲经济区（EEA）境内（如德国法兰克福机房）**。如果私自将这批包含欧洲公民身份与商业税务的数据发往境外服务器，在法律层面上等同于直接侵犯了该国的数据主权！

### 2. 什么是“跨境合规”（Cross-border Compliance & SCC）？
* **大白话定义**：**“如果企业非要跨国调取数据，必须持有当地法律认可的‘数据护照与通关签证’，否则就是‘非法偷渡’！”**
* **电商退赔中的现实架构冲突**：  
  * 企业的订单库和业务中台部署在**欧洲法兰克福（AWS eu-central-1）**；
  * 但目前全球推理能力最强的闭源大模型（如 OpenAI GPT-4o、Anthropic Claude 3.5 Sonnet）的官方主集群部署在**美国美东（AWS us-east-1）**。
  * **法律冲突点**：当 Agent 组装好 Prompt，向美东大模型发起 HTTP POST 请求的一瞬间，网络数据包跨越大西洋，从法律上已经构成了**“个人数据跨境传输（Cross-border Data Export）”**！
  * **通关签证（SCC / DPF）**：企业必须事先与模型服务商签署经欧盟委员会批准的《标准合同条款》（Standard Contractual Clauses, **SCC**），或者服务商必须通过《欧美数据隐私框架》（EU-US **DPF**）认证。如果缺乏该法定文书，即使企业对数据做了脱敏，该次跨境请求依然属于**违法出境**。

### 3. 什么是“物理熔断”（Physical Circuit Breaking）？
* **大白话定义**：**“绝不是在日志里打印一句 warning，而是在底层网络栈直接‘拉闸断电、拔掉网线’，绝不让一个非法字节飞出国门！”**
* **为什么必须是“物理”熔断？**  
  在传统粗糙系统中，合规检查往往只是 `if (!compliant) logger.warn("出境违规");`，随后代码依然放行，外部 HTTP 请求依然照常发出。  
  在受控宿主运行时（Harness）的 Hook 2 门禁中，**物理熔断是内核级硬约束**：  
  一旦合规引擎计算出“目标模型位于境外且无有效 SCC”，门禁立即抛出不可捕获的 `DataSovereigntyViolationException`，并在操作系统网络层**强制向 TCP Socket 发送 RST 报文关闭连接**，彻底阻断传输！

### 4. 什么是“本地主权降级”（In-Region Sovereign Fallback）？
* **大白话定义**：**“境外大模型去不了，绝不能让退赔业务挂死，立刻就地无缝切换至境内的自建开源大模型！”**
* **在售后退赔 Agent 中的自愈表现**：  
  当美东 Claude 3.5 因数据主权被物理熔断后，Harness 的容灾机制立即接管，**在 5 毫秒内将 Prompt 路由重定向至部署在法兰克福本地 Kubernetes 集群的开源大模型（如 Qwen-2.5-72B 或 Llama-3.1-70B）**。  
  本地开源模型虽然比顶尖闭源模型参数量稍小，但足以完成划痕图质检核验与逆向物流运费计算。**整个过程买家完全无感知，业务平稳闭环，且 100% 遵守欧盟数据驻留法！**

## 第四章：生产级工程落地代码范式（Java 21 范式）

### 1. 跨境合规门禁计算引擎

```java
package com.cogniva.agent.harness.compliance;

import java.net.InetAddress;
import java.net.URI;
import java.util.Set;
import java.util.Objects;

/**
 * Hook 2 功能五：数据主权与跨境合规物理熔断门禁核心引擎
 */
public final class CrossBorderDataSovereigntyBarrier {

    private final String tenantId;
    private final String sourceJurisdiction; // 数据产生地，如 "EU-FR"
    private final Set<String> activeLegalAgreements; // 租户签署的生效协议集合，如 ["SCC-2026-US-ANTHROPIC"]

    public CrossBorderDataSovereigntyBarrier(String tenantId, String sourceJurisdiction, Set<String> activeLegalAgreements) {
        this.tenantId = Objects.requireNonNull(tenantId);
        this.sourceJurisdiction = Objects.requireNonNull(sourceJurisdiction);
        this.activeLegalAgreements = Objects.requireNonNull(activeLegalAgreements);
    }

    /**
     * 出网前决策评估：若跨国传输且缺少法律通关凭证，立即物理熔断
     * @param targetEndpoint 目标模型推理 API URI (如 "https://api.anthropic.com/v1/messages")
     * @param hasSovereignTaxData 是否包含法国发票、税号等不可脱敏的主权凭据
     */
    public RoutingDecision evaluateOutboundCompliance(URI targetEndpoint, boolean hasSovereignTaxData) {
        String destinationCountry = resolveTargetCountry(targetEndpoint);

        // 规则 1：境内同区域流动 (EU -> EU)，天然符合主权驻留规范
        if (sourceJurisdiction.startsWith("EU") && "EU".equalsIgnoreCase(destinationCountry)) {
            return new RoutingDecision(Verdict.PERMITTED_DOMESTIC, targetEndpoint);
        }

        // 规则 2：跨境跨大西洋流动 (EU -> US)
        if (sourceJurisdiction.startsWith("EU") && "US".equalsIgnoreCase(destinationCountry)) {
            String requiredSccCode = "SCC-2026-US-" + extractProvider(targetEndpoint);
            
            // 审查法定合同条款 (SCC)
            if (activeLegalAgreements.contains(requiredSccCode)) {
                return new RoutingDecision(Verdict.PERMITTED_CROSS_BORDER_WITH_SCC, targetEndpoint);
            }

            // 【触发物理熔断】：无协议非法出境，硬性阻断
            throw new DataSovereigntyViolationException(String.format(
                "CRITICAL COMPLIANCE BLOCK: Cross-border export of tenant [%s] data from [%s] to [%s] blocked! Missing required legal instrument: [%s].",
                tenantId, sourceJurisdiction, destinationCountry, requiredSccCode
            ));
        }

        return new RoutingDecision(Verdict.PERMITTED_DOMESTIC, targetEndpoint);
    }

    private String resolveTargetCountry(URI uri) {
        String host = uri.getHost().toLowerCase();
        if (host.contains("eu-central") || host.contains(".eu.") || host.endsWith(".eu")) {
            return "EU";
        }
        return "US"; // 默认美东主集群
    }

    private String extractProvider(URI uri) {
        String host = uri.getHost().toLowerCase();
        if (host.contains("anthropic")) return "ANTHROPIC";
        if (host.contains("openai")) return "OPENAI";
        return "GENERIC_CLOUD";
    }

    public enum Verdict {
        PERMITTED_DOMESTIC,
        PERMITTED_CROSS_BORDER_WITH_SCC
    }

    public record RoutingDecision(Verdict verdict, URI designatedEndpoint) {}
}
```

### 2. 物理熔断后的本地主权自愈重定向（Sovereign Fallback Router）

```java
package com.cogniva.agent.harness.compliance;

import java.net.URI;
import java.util.logging.Logger;

/**
 * 物理熔断发生后的主权算力自愈路由工厂
 */
public final class SovereignFallbackRouter {

    private static final Logger LOGGER = Logger.getLogger(SovereignFallbackRouter.class.getName());
    
    // 欧洲法兰克福本地自建开源大模型集群端点
    private static final URI FRANKFURT_LOCAL_CLUSTER = URI.create("http://llm-sovereign-mesh.eu-central-1.internal/v1/chat/completions");

    public static URI determineExecutableEndpoint(CrossBorderDataSovereigntyBarrier barrier, URI preferredRemoteEndpoint, boolean containsSovereignData) {
        try {
            // 首选尝试远程闭源模型出网评估
            CrossBorderDataSovereigntyBarrier.RoutingDecision decision = 
                barrier.evaluateOutboundCompliance(preferredRemoteEndpoint, containsSovereignData);
            return decision.designatedEndpoint();
        } catch (DataSovereigntyViolationException ex) {
            // 捕获合规物理熔断，立即就地激活本地主权算力降级
            LOGGER.warning("Data sovereignty barrier tripped! Activating in-region sovereign fallback: " + ex.getMessage());
            return FRANKFURT_LOCAL_CLUSTER; // 无缝重定向至本地法兰克福 Qwen-2.5-72B / Llama-3.1-70B 节点
        }
    }
}
```

## 第五章：高频面试与架构评审硬核考点

### Q1: “既然前面功能三已经对信用卡号和姓名做了加盐代币化，数据已经不是明文了，为什么还会触犯数据主权而需要物理熔断？”
> **深度拆解**:  
> 这是一个极具专业深度的架构考点：
> 1. **PII 脱敏 $\ne$ 商业与税务主权豁免**：在欧洲买家 Alice 的工单中，除了姓名和卡号，还附带了**法国增值税发票（含 Numéro Fiscal 税号）、带有巴黎地理位置（GPS EXIF）的手表瑕疵照片、以及特定订单货值和关税明细**。依据 GDPR 与法国商法典，这些属于**法定本土商业主权数据**，不属于普通的 PII，单纯的姓名打码不能免除其“数据跨境监管”义务。  
> 2. **元数据关联与反向定长推断**：即使文本中只有代币，整个 Prompt 的特定发票行号、商品 EAN 条码和纠纷上下文，一旦流出欧盟境外的第三方云机房，境外机构依然可以通过上下文拼图推断出商业主权信息。因此，必须从**物理数据流层面**进行绝对驻留控制。

### Q2: “物理熔断并降级到法兰克福本地开源模型后，若本地模型能力不足导致退赔判决失误怎么办？”
> **深度拆解**:  
> 1. **任务复杂度分流（Task Complexity Triage）**：售后争议退赔的核心任务是**“划痕质检判定”**与**“逆向运费比较公式”**。现代优秀的开源大模型（如 Qwen-2.5-72B 或 Llama-3.1-70B）在结构化函数调用（Function Calling）和特定决策规则上，其准确率已经高达 98% 以上，完全能够胜任售后退赔任务；  
> 2. **兜底人工接管（Human-In-The-Loop Fallback）**：若本地模型给出的置信度得分低于阈值（如 `< 0.85`），Harness 控制环并不冒险下发退款动作，而是平滑将工单挂起并流转至欧盟本地法兰克福客服中心的人工审核工作台，既守死了资金安全，又 100% 遵守了法律。
