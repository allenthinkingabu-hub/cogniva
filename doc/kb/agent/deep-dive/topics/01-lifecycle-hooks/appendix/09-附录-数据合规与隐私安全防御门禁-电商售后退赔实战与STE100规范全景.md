## 一、 维度二四大防御关卡端到端实战解构

### 第一关：功能二实战——授权目的绑定与用户同意权核验（Purpose Binding & Consent）

#### 1. 业务车祸实况（未经门禁）
CRM 系统为了查询方便，通常提供宽表数据接口，一口气吐出 50+ 字段，包含：
* 买家绑定的社媒账号、过去 6 个月在独立站搜索“脱发治疗”、“抗抑郁药”等**极度敏感的健康浏览隐私**；
* 买家在其他类目（如成人用品、母婴商品）的消费记录；
* 客服早年间记录的闲聊标签：`"性格急躁、爱占小便宜"`。

#### 2. Hook 2 门禁硬核处置
* **识别目的代码（Purpose Code）**：当前任务的授权目的代码为：
  `PURPOSE_AFTER_SALE_REFUND_ARBITRATION`（售后退赔仲裁）；
* **匹配字段白名单掩码（Field Masking）**：
  依据欧盟 GDPR 第 5 条“最小必要原则”（Data Minimisation），退赔仲裁**只需要**：`订单货值`、`妥投时间`、`质检报告`、`过去90天纠纷率`；
* **物理剥离非关联数据**：
  Hook 2 直接在内存中将健康浏览记录、无关类目订单、客服主观评价**彻底物理剥离丢弃**；
* **GDPR 同意权（Consent）核验**：
  核查买家的隐私偏好设置。若发现该买家上周曾点击了《撤回自动化画像决策权（Right to Object under GDPR Art.21）》，门禁当场抛出 `ConsentWithdrawnException`，**直接阻断 Agent 自动推理，秒级转入人工工单池**，杜绝行政违法！

### 第三关：功能四实战——加盐隔离的临时可逆代币保险库（Java 21 Ephemeral Vault）

大模型面对 `{{CREDIT_CARD_1}}` 可以完美进行退赔推理（大模型不需要知道真实卡号，它只需要知道“卡号合法，可以原路打款”）。
但是，**当大模型决策同意退款后，后续真实的退款服务怎么知道退给谁？**

#### Hook 2 的 Java 21 堆内存加盐保险库机制：
在当前 Worker 进程的 JVM 堆内存中，开辟单次 Run 独占的加盐映射容器：

```java
package com.cogniva.agent.harness.security;

import java.util.Map;
import java.util.Objects;
import java.util.UUID;
import java.util.concurrent.ConcurrentHashMap;

/**
 * Java 21 堆内存临时可逆保险库实体
 * 严格生命周期管理：仅在当前 Worker JVM 堆内存中存活，严禁落盘入库
 */
public final class EphemeralPiIVault {

    private final String runId;
    private final String saltNonce; // 单次 Run 专属随机盐，防止彩虹表反向碰撞
    private final Map<String, String> tokenToRawMap;
    private final Map<String, String> rawToTokenMap;
    private volatile boolean isDestroyed = false;

    private EphemeralPiIVault(String runId, String saltNonce) {
        this.runId = Objects.requireNonNull(runId);
        this.saltNonce = Objects.requireNonNull(saltNonce);
        this.tokenToRawMap = new ConcurrentHashMap<>();
        this.rawToTokenMap = new ConcurrentHashMap<>();
    }

    public static EphemeralPiIVault create(String runId) {
        String salt = UUID.randomUUID().toString().replace("-", "").substring(0, 12);
        return new EphemeralPiIVault(runId, salt);
    }

    /**
     * 注册敏感数据，生成加盐安全代号
     */
    public String register(String rawPii, String typePrefix) {
        ensureActive();
        return rawToTokenMap.computeIfAbsent(rawPii, key -> {
            String token = String.format("{{%s_%d}}", typePrefix, tokenToRawMap.size() + 1);
            tokenToRawMap.put(token, rawPii);
            return token;
        });
    }

    /**
     * 仅供特权内网结算网关（Ring-0）在退款执行时调用回填
     */
    public String resolve(String token) {
        ensureActive();
        return tokenToRawMap.get(token);
    }

    /**
     * 判定当前代号是否属于合法注册白名单（防模型幻觉）
     */
    public boolean containsToken(String token) {
        ensureActive();
        return tokenToRawMap.containsKey(token);
    }

    /**
     * 由 Hook 8 在生命周期终态时触发内存物理清空与置零
     */
    public synchronized void zeroizeAndDestroy() {
        if (!isDestroyed) {
            tokenToRawMap.clear();
            rawToTokenMap.clear();
            this.isDestroyed = true;
        }
    }

    private void ensureActive() {
        if (isDestroyed) {
            throw new IllegalStateException("EphemeralPiIVault has already been destroyed for runId: " + runId);
        }
    }
}
```

* **加盐映射存储**：
  * `{{CREDIT_CARD_1}}` $\longrightarrow$ `4111-2222-3333-4444`
  * `{{BUYER_NAME_1}}` $\longrightarrow$ `Jean-Luc Moreau`
* **三道安全红线**：
  1. **严禁写入 Redis / 数据库**：哪怕数据库被黑客拖库，黑客也拿不到这个映射关系；
  2. **严禁序列化进日志**：日志框架（Logback/SLF4J）打印时，该 Vault 对象被强行脱壳抹平；
  3. **受控回填（De-tokenization）**：后续大模型给出裁决后，仅在企业受信任的内网结算网关（Ring-0），由特权进程读取该内存映射，向 Stripe 真正发起退款调用；调用完毕后由 Hook 8 将该内存执行**物理置零（Zeroization）清空**。

### 第四关：功能五实战——数据主权与跨境合规物理熔断门禁（Cross-border Sovereignty）

#### 1. 业务现实挑战
* 买家位于**法国巴黎（欧盟境内）**；
* 平台配置的主模型网关由于成本考虑，被路由到了位于**美东俄亥俄州（US-East）的 AWS 数据中心**。
* 依据欧盟 Schrems II 判决与 GDPR Chapter V 规定：**将欧洲公民的核心身份与消费特征传输至美国机房，属于跨境数据出境（Data Transfer to Third Countries）**，必须具备标准合同条款（SCC）或经过充分性认定。

#### 2. Hook 2 门禁判定与物理降级动作
```
   [当前买家居留地: 欧盟法兰西 (FR)] ──► [目标推理节点: 美国美东 (US-East)]
                                    │
                                    ▼ (计算数据主权合规策略)
                 ┌──────────────────────────────────────┐
                 │ 判定 1: 文本中是否依然存在敏感元数据? │
                 │ 判定 2: 是否签署合法数据跨境传输协议? │
                 └──────────────────┬───────────────────┘
                                    │ (未签署跨境协议 / 属于主权受限类目)
                                    ▼
                 [ 触发数据主权物理熔断与本地降级流水线 ]
                                    │
    ┌───────────────────────────────┴───────────────────────────────┐
    ▼ (严禁向美东外发任何网络数据包)                                  ▼ (就地重定向模型路由)
【抛出 DataSovereigntyViolationException】         【无缝重定向至欧盟境内法兰克福自建私有化模型】
(0 字节数据流出欧洲，完全守死合规底线)                (在法兰克福内网完成全部推理，零跨境合规风险)
```

* **处置策略**：
  * 若当前商品类目属于欧盟严格受控类目且未配置跨境通道，Hook 2 坚决执行**物理熔断**，拦截向美东外发 HTTP 请求；
  * **动态降级**：通知路由网关将请求**就地重定向至部署在德国法兰克福（eu-central-1）的私有化开源大模型（如本地部署的 LLaMA-3 / Mistral-Large）**，在欧盟物理领土内完成闭环推理！

## 三、 基于 ASD-STE100 规范的数据合规与隐私安全工程规范

本章节遵循国际航空航天与国防工业标准 **ASD-STE100（Simplified Technical English）** 编写。通过严格受控词汇、短句结构（$\le 20$ 词）与主动语态，消除多语言工程师在实现数据合规门禁时的歧义。

### SECTION 1: PURPOSE AND DEFINITIONS / 目的与术语定义

#### STE English:
1. This section gives technical rules for data compliance and privacy gates.
2. **Personally Identifiable Information (PII)**: Any data item that identifies a natural person. Examples are names, addresses, and phone numbers.
3. **Primary Account Number (PAN)**: The complete credit card number of 16 digits.
4. **Purpose Limitation**: A legal rule under GDPR. You must collect data only for a declared business goal.
5. **Ephemeral Vault**: A temporary in-memory lookup table. It stores token mappings only during the run.
6. **Data Sovereignty**: The legal rule that requires consumer data to stay inside designated geographic borders.

#### 标准中文对照：
1. 本章节给出数据合规与隐私安全门禁的技术规范规则。
2. **个人身份信息 (PII)**：可识别自然人身份的任意数据项。例如姓名、地址与电话号码。
3. **主账号 (PAN)**：由 16 位数字组成的完整信用卡号。
4. **目的限制原则**：GDPR 项下的法定原则。系统收集数据必须仅用于已声明的业务目标。
5. **临时保险库 (Ephemeral Vault)**：临时内存查找表。它仅在运行生命周期内保存代号映射。
6. **数据主权**：强制要求消费者数据留存在指定地理边界内的法律规定。

---

### SECTION 2: OPERATIONAL RULES AND TECHNICAL INVARIANTS / 操作规程与不可变技术约束

#### STE English:
1. The harness must verify the `purpose_code` before it reads customer data.
2. Do not include customer browsing history in the prompt.
3. Do not include non-related order history in the prompt.
4. If the customer removed consent, stop the run immediately.
5. If the run stops for consent, write an audit record and alert human operators.
6. The engine must scan all text for credit card numbers.
7. The engine must use the Luhn algorithm to validate every matched credit card candidate.
8. If the card number is valid, replace it with `{{CREDIT_CARD_X}}`.
9. The worker must store the real card number only in the `EphemeralPiIVault`.
10. Do not write the `EphemeralPiIVault` to persistent disks.
11. Do not send the `EphemeralPiIVault` to shared Redis caches.
12. Do not write raw credit card numbers to application log files.
13. If the model output contains a new token not in the vault, reject the output.
14. When the run finishes, call `zeroizeAndDestroy()` to erase the vault memory.
15. If European Union data cannot leave the region, do not send the prompt to United States servers.
16. If data transfer is illegal, redirect the prompt to the local European model node.

#### 标准中文对照：
1. Harness 在读取客户数据之前，必须先核查 `purpose_code`。
2. 严禁在提示词中包含客户的浏览历史记录。
3. 严禁在提示词中包含非关联的历史订单记录。
4. 若客户已撤回数据处理同意权，立即终止该任务运行。
5. 若任务因同意权撤回而终止，写入审计日志并通知人工处理。
6. 引擎必须扫描文本中所有信用卡号。
7. 引擎必须使用 Luhn 算法校验每个匹配到的疑似信用卡候选数据。
8. 若信用卡号合法，将其替换为 `{{CREDIT_CARD_X}}`。
9. 工作节点必须仅将真实卡号保存在 `EphemeralPiIVault` 堆内存中。
10. 严禁将 `EphemeralPiIVault` 写入持久化存储介质。
11. 严禁将 `EphemeralPiIVault` 发送到共享的 Redis 缓存。
12. 严禁将原始信用卡明文卡号写入应用程序日志文件。
13. 若模型输出中包含了未在保险库中注册的新代号，拒绝该输出。
14. 当任务运行结束时，调用 `zeroizeAndDestroy()` 擦除保险库堆内存。
15. 若欧盟数据法律禁止出境，严禁将提示词发送至美国服务器。
16. 若跨国数据传输不合法，将提示词请求重定向至欧盟本地模型节点。

### SECTION 3: FAILURE CONDITIONS AND CORRECTIVE ACTIONS / 故障条件与修正动作

#### STE English:
1. **Condition A: Consent Check Fails**:
   * Cause: The customer selected "Opt-out" in privacy settings.
   * Action: Throw `ConsentWithdrawnException`.
   * Action: Delete the distributed lease in Redis.
   * Action: Forward the dispute ticket to the manual customer service queue.
2. **Condition B: Raw Credit Card Found in Prompt**:
   * Cause: The regex or Luhn scanner failed.
   * Action: Throw `ComplianceViolationException`.
   * Action: Block the outbound HTTP connection to the LLM vendor.
   * Action: Record a critical security alert with the run identifier.
3. **Condition C: Cross-Border Sovereignty Violation**:
   * Cause: Network router tries to send European data to an unapproved region.
   * Action: Throw `DataSovereigntyViolationException`.
   * Action: Route the request to the Frankfurt failover model cluster.

#### 标准中文对照：
1. **故障条件 A：用户同意权校验失败**：
   * 触发起因：客户在隐私设置中选择了“Opt-out（退出自动化处理）”。
   * 修正动作：抛出 `ConsentWithdrawnException` 异常。
   * 修正动作：删除 Redis 中的分布式租约。
   * 修正动作：将该争议工单转发至人工客服排队队列。
2. **故障条件 B：提示词中发现原始信用卡明文**：
   * 触发起因：正则表达式或 Luhn 扫描引擎漏检。
   * 修正动作：抛出 `ComplianceViolationException` 合规阻断异常。
   * 修正动作：物理切断向外部大模型厂商外发 HTTP 网络连接。
   * 修正动作：记录包含当前运行标识符的高危安全报警日志。
3. **故障条件 C：违反跨国数据主权出境法规**：
   * 触发起因：网络路由层企图将欧洲公民数据发送至未授权地域。
   * 修正动作：抛出 `DataSovereigntyViolationException` 数据主权异常。
   * 修正动作：将模型请求路由至法兰克福容灾备用模型集群。
