## 3. Technology Selection, Compatibility, and Framework Baseline

### 3.1 Decision Levels and Baseline Evaluation

"Selected Framework" indicates the recommended implementation choice in this specification; "Candidate Line" is used for G0 concrete patch resolution; "Production Locked" strictly requires BOM/lockfile, image digest, vendor support window, license review, vulnerability scanning, and PoC benchmark evidence.

| Domain | Selected Framework | Candidate Baseline / Verification Criteria |
|---|---|---|
| **Java Runtime / Build** | JDK 21 LTS, Maven Wrapper, Spring Boot / Cloud / Alibaba | Spring Boot 4.0.x + Cloud 2025.1.x + Alibaba 2025.1.0.0; PoC verified as a compatibility group; do not blindly bump Boot |
| **Java HTTP / Auth** | Spring MVC, Validation, Security OAuth2 Resource Server; Gateway independent app | REST boundary, workload JWT; long-running model inferences must not block MVC threads; no second agent orchestrator in Java |
| **Java Persistence** | Spring JDBC / `JdbcClient`, Declarative Transactions, Flyway | Explicit SQL for reliable CAS and Outbox; avoid mixing multiple ORMs initially; drivers verified via BOM |
| **Java Messaging / Testing** | Spring AMQP, JUnit 5, Testcontainers, ArchUnit | RabbitMQ protocol, real PostgreSQL/AMQP containerized tests; version aligned with Boot BOM |
| **Python Runtime / Packaging** | CPython 3.14 standard GIL build, uv, `src/` layout | Maintained line; verify native wheels; free-threading disabled by default; 3.13 serves as fallback with approved PoC evidence |
| **Python HTTP / Types** | FastAPI, Uvicorn, Pydantic v2, pydantic-settings | Internal RPC/health checks; strict DTO + independent JSON Schema validation; synchronous libraries must not block event loop |
| **Agent Orchestration** | LangGraph 1.x with PostgreSQL checkpointer; Native Agent Interfaces | Graphs pinned per run version; LangGraph acts as graph execution engine, Harness handles business transactions/fencing/idempotency |
| **Python Data Access** | SQLAlchemy 2.1 async Core + psycopg 3, Alembic | SQLAlchemy 2.0 maintenance line as fallback; independent transaction/connection per task; no shared concurrent `AsyncSession` |
| **Python Messaging / HTTP** | aio-pika, HTTPX, asyncio | Robust connections handle transport recovery, business layer requires Inbox/Outbox; HTTPX uses bounded client pools and explicit timeouts |
| **Model Connectivity** | Native `ProviderPort` + isolated Model Provider Service; `FakeProvider` first | Physical isolation: API keys decrypted only inside Provider process; Agent code never imports vendor SDKs directly |
| **RAG & Search** | PostgreSQL relational/lexical + dictionary + pgvector; Python fusion & evidence assembly | Chinese tokenization verified against gold queries; no default English stemmer; no standalone vector database in initial phase |
| **Data / Queue / Cache** | PostgreSQL, RabbitMQ, Valkey, S3-compatible Object Storage | Standard enterprise topology; exact patches locked in G0; cache is never treated as authoritative business ledger |
| **Python Quality Engineering** | pytest, pytest-asyncio, Ruff, mypy, jsonschema, Testcontainers | Exact schema match; property/fault/permission tests; real model benchmarking separated into dedicated queue with budget |
| **Observability** | OpenTelemetry, Structured JSON Logging, Prometheus / Grafana | Unified trace/run/step/cycle correlation; OpenTelemetry GenAI semantic conventions pinned; no raw PII in logging |
| **Deployment / Delivery** | Docker / OCI, Kubernetes, Kustomize, Argo CD (GitOps) | Platform-neutral CI task specs; production delivery requires protected repos, signed container images, and staged promotion |

*Design Rule*: Celery as cross-language protocol, MCP/A2A, Service Mesh, Seata, standalone search clusters, and automatic multi-provider switching are omitted from the initial baseline. Adopting Spring Cloud Alibaba does not permit indiscriminately enabling all its subcomponents.

### 3.2 Compatibility Matrix and Source Validation

1. **Spring Cloud Compatibility Matrix**: Boot 4.0.x is verified against Cloud 2025.1.x and Alibaba 2025.1.0.0. Components must be evaluated together; supporting Boot 4.1 in Cloud does not imply full Alibaba compatibility.
2. **Python Support Lifecycle**: Python 3.14 is in bugfix and 3.13 in security maintenance. 3.14 is recommended, with 3.13 retained as fallback.
3. **Engine Guidelines**:
   - [FastAPI Async Documentation](https://fastapi.tiangolo.com/async/) & [Pydantic v2](https://docs.pydantic.dev/latest/): Models must use strict validation and non-blocking handlers.
   - [LangGraph Persistence](https://docs.langchain.com/oss/python/langgraph/persistence): Checkpointing provides step replay, not distributed exactly-once side-effect guarantees.
   - [RabbitMQ Publisher Confirms](https://www.rabbitmq.com/docs/confirms): Publisher confirm guarantees broker receipt, separated from consumer transactional processing.
   - [aio-pika](https://docs.aio-pika.com/): Async AMQP client requires explicit transaction coordination via local Inbox table.

### 3.3 G0 Technology Lock Manifest Requirements

The G0 phase must output a deterministic `dependency-lock-manifest.json`:
- JDK release, distribution vendor, and Maven Wrapper SHA-256 hash.
- Spring Boot / Cloud / Alibaba BOM coordinates and dependency tree convergence audit.
- Python minor version, uv version, generated `uv.lock`, and package integrity hashes.
- Database, extension (`pgvector`), broker, cache, and IAM runtime versions.
- Base container image digests, target Kubernetes version, and ModelProfile definitions.
- License compliance matrix and vendor support expiration owners.
- Upper version bounds are solely for solver constraints; CI must enforce `--frozen` lockfiles.

### 4.2 Harness Host Control Ring and 9-Stage Lifecycle Hooks

The scaffold enforces the core architectural invariant: **"LangGraph serves as the directed graph execution engine; Harness serves as the supervisory Host Control Ring."**

```text
advance(run, fencing_token):
  load pinned release and durable state
  verify lease, tenant, cancellation, deadline, authorization freshness
  reconcile any pending or unknown external operation before resending
  select ready step from approved workflow
  assemble protected context; resolve approved skills; reserve model budget
  choose deterministic rule OR invoke approved model
  validate candidate schema, evidence and legal action set
  for each selected action within bounded concurrency:
    verify dependency, latest scope, cancellation and resource revision
    authorize action; reserve its budget
    persist tool/delegation intent with stable operation_ref
    execute via adapter, record result OR unknown status
    validate output, sanitize untrusted content, record usage/receipt
  checkpoint durable progress
  evaluate done / wait / no-progress / budget / deadline / cancellation
  finalize atomically OR persist wait / enqueue next bounded step
```

#### The 9-Stage Lifecycle Interceptors (Non-Bypassable):
1. **`on_run_load`**: Loads immutable run profile, validates tenant identity, distributed lease, and cancellation tombstone; aborts revoked or superseded executions.
2. **`before_context`**: Validates student consent freshness and purpose; re-reads authoritative business facts; strips unauthorized or stale context segments.
3. **`before_model`**: Estimates token usage, checks outbound endpoint allowlist, atomically reserves model budget, and verifies execution cancellation flags.
4. **`after_model`**: Strictly parses structured JSON schema, records actual token usage and provider latency, intercepts unauthorized escalation, and handles refusals.
5. **`before_action`**: **Critical Security Gate**. Only the Harness host can construct an `AuthorizedToolCall` from untrusted model proposals. Any candidate self-asserting `permit=true` is intercepted and blocked by host code.
6. **`after_action`**: Persists a globally unique business operation key (`operation_ref`), verifies payload hash, and flags network timeouts as `unknown` (never assuming failure).
7. **`before_checkpoint`**: Enforces a monotonically increasing `fencing_token` with CAS optimistic concurrency control to persist state; split-brain writes from stale workers are rejected.
8. **`before_finalize`**: Aggregates achieved milestones, pending confirmations, and unfulfilled obligations; compiles the multi-agent execution receipt.
9. **`after_finalize`**: Publishes terminal execution events and sanitized audit logs via Outbox pattern.

#### Core Harness Mechanisms:
- **Physical Secret Boundary**: `cogniva-learning-agent` never holds raw LLM API keys; it communicates exclusively with `cogniva-model-provider` over internal RPC/HTTP. Local testing defaults to a 100% deterministic `FakeProvider`.
- **Operation Idempotency & Reconciliation**: All tool calls and external proposal submissions require a pre-persisted `operation_ref`. Network timeouts are recorded as `unknown` and audited by a background Reconciler with exponential backoff.
- **Protected Long Context**: System prompts, negative student constraints (e.g., "no civil law on weekends"), and active goals are protected segments exempt from naive sliding-window truncation. Produces an explicit `ContextManifest`.
- **Atomic Budget Conservation**: Parent agents reserve total budget; child agent delegations slice sub-budgets such that `child_allocation + parent_spent <= total_authorized_budget`.
- **No-Progress Circuit Breakers**: Max steps, deadlines, budget limits, and a rule intercepting 3 consecutive state-identical action hashes immediately trip the circuit breaker.
- **Bidirectional Stubs**: Built-in `JavaStub` (enables Python testing without live Java services) and `AgentStub` (enables Java testing without live Python services).

### 4.3 Composition Root and Unidirectional Dependency Direction

FastAPI lifespan initializes: `Settings` → Contract/Prompt/Policy/Graph Manifest validation → HTTP/SQL/AMQP connection pools → Adapters → `AgentRegistry` / `GraphRegistry` → Application Services.
Graceful shutdown stops receiving new tasks, sets `readiness=false`, waits for in-flight requests within a bounded grace period, flushes Outbox, and releases distributed leases/connections. Importing a module must never trigger network calls or auto-run database migrations.

- **Unidirectional Dependency Flow**:
  $$\text{Domain (Pure / Zero 3rd-party)} \longleftarrow \text{Ports (Abstract Interfaces)} \longleftarrow \text{Harness (Control Ring)} \longleftarrow \text{Workflows / Agents} \longleftarrow \text{Adapters (FastAPI, SQLAlchemy, LangGraph, ProviderClient)}$$
- **Strict Invariant**: Agents must never directly import SQLAlchemy, HTTPX, or vendor LLM SDKs, nor read raw secrets from environment variables.
- **Java Layer Boundary**: Controller → Application Service → Domain Policy / Repository Port. JDBC and AMQP implementations reside strictly in the infrastructure package. Workload JWT authentication is isolated from public student session tokens.

### 4.5 Scaffold Minimum Viable Chain Acceptance and Non-Functional Hard Invariants

The minimal end-to-end acceptance flow executes:
$$\text{Synthetic Submission} \longrightarrow \text{Java Outbox} \longrightarrow \text{RabbitMQ} \longrightarrow \text{Python Inbox/Run} \longrightarrow \text{Routing to LA-02 (FakeProvider)} \longrightarrow \text{Proposal Delivery} \longrightarrow \text{Java Validation \& Receipt} \longrightarrow \text{GET /runs/\{ref\}}$$

The scaffold is certified as ready only when all 6 Non-Functional Hard Invariants (**S-NFR**) pass:
1. **S-NFR-01 Zero-Trust Security**: Worker processes hold zero LLM API keys. `before_action` intercepts candidate model proposals spoofing `permit=true`. Student PII in audit logs is automatically masked.
2. **S-NFR-02 Idempotency & Fault Recovery**: Replaying the same answer submission 10 times results in exactly 1 business state mutation. A killed worker automatically resumes from its last persistent checkpoint upon reboot. Stale lease writes are 100% blocked by CAS fencing.
3. **S-NFR-03 Deterministic Local Loop**: Relies entirely on `FakeProvider` and synthetic data. All unit and contract test suites execute 100% offline in < 5 seconds.
4. **S-NFR-04 Bounded Concurrency**: Asynchronous non-blocking architecture (FastAPI + asyncpg + HTTPX). Child agent delegation depth is bounded at `max_depth <= 2`.
5. **S-NFR-05 Auditable Observability**: Complete correlation across `trace_id`, `run_ref`, `step_index`, and `operation_ref`. High-risk proposal audit logs are exempted from probabilistic sampling.
6. **S-NFR-06 Architectural Purity**: Swapping out LangGraph or the underlying LLM provider requires zero modifications to agent domain logic or intent rules.

## 5. Types, Ports, Errors, and Execution Context

### 5.1 Type Mapping and Schema Compatibility

- **Authoritative Source**: JSON Schema Draft 2020-12 and OpenAPI 3.1.
- **Python Mapping**: Pydantic v2 DTOs with `frozen=True` and `extra="forbid"`. Lenient type coercion (such as treating booleans as integers) is explicitly forbidden.
- **Java Mapping**: Immutable Java `records` / POJOs with Bean Validation constraints.
- **Canonical Serialization**: Idempotency payload hashes use canonical JSON: deterministic key sorting, UTF-8 encoding, explicit representation of null vs. omitted fields, excluding transient trace headers.
- **Identifiers**: External public references (`public_ref`, string) are decoupled from internal database UUIDs. Monetary amounts and token counts use 64-bit integers (smallest subunit) or `Decimal`, never IEEE 754 floating-point numbers.

### 5.2 Hexagonal Ports Architecture

The core domain and Harness interact with infrastructure through strongly-typed abstract ports:

| Port | Core Method Signatures | Responsibility & Security Boundary |
|---|---|---|
| **ModelPort** (`ModelGatewayPort`) | `reserve(spec)`, `submit(payload)`, `query(id)`, `settle(usage)` $\to$ `ModelResult` | Abstract LLM gateway; handles retries and unknown usage accounting |
| **PolicyPort** (`ContextResolverPort`) | `resolve(refs, purpose, auth_ref)` $\to$ `AuthorizedContext` | Validates student consent and time window; issues least-privilege context |
| **BudgetPort** | `reserve(...)`, `allocate(...)`, `record_usage(...)`, `settle(...)`, `release(...)` | Token and monetary budget governance; atomically carves sub-budgets for sub-agents |
| **CheckpointPort** (`RunRepository`) | `get(run_ref)`, `save_checkpoint(state)`, `cas_transition(fence)` | Durable step checkpointing and state transitions; validates monotonic `fencing_token` |
| **ReceiptPort** (`ProposalPort`) | `submit_proposal(kind, payload, operation_ref)` $\to$ `Receipt` | Submits candidate proposals to Java Core and retrieves authoritative business receipts |
| **EvidencePort** (`EvidenceRetrieverPort`) | `retrieve(query, auth_scope)` $\to$ `EvidenceSet` | Authorized knowledge and document retrieval with provenance and version metadata |
| **ToolPort** | `execute(invocation, verified_context)` $\to$ `ToolResult` | Governed action execution; enforces pre-persisted `operation_ref` and tool allowlist |
| **LeasePort** | `claim(run_ref)`, `renew(...)`, `release(...)` $\to$ `LeaseTicket` | Distributed execution lease coordination; Java/DB serves as clock authority |
| **AgentPort** | `execute(invocation, agent_context)` $\to$ `RoleOutput` | Specification for LA-01~05 agents; outputs typed candidate proposals |

### 5.3 AgentContext and GraphState

- **`AgentContext`**: Holds invocation parameters, verified identity, authorization scope, versioned policy manifest, prompt manifest, model profile, deadline timestamp, budget view, read-only tool registry, and trace context. Sensitive credentials and database connection pools are excluded.
- **`GraphState`**: Stores run epoch, input entity references, step output references, receipts, branch execution states, and error summaries. Large textual evidence is referenced via immutable handles in `EvidenceSet`.
- **Parallel Reducers**: Parallel graph branches (e.g., `analysis_ref`, `explanation_receipt`, `personal_receipt`) use dedicated state attributes; concurrent appending to a shared mutable list is forbidden. State reductions enforce conflict detection on identical step keys with differing payload hashes.

### 5.4 Error Taxonomy and Propagation

Domain errors are structured as `DomainError(code, retryable, source, correlation_ref, safe_details)`:
- `ContractViolation`: Non-retryable; triggers request rejection (HTTP 422).
- `AuthorizationDenied`: Non-retryable; terminates execution flow (HTTP 403).
- `VersionConflict`: Stale revision or fencing token mismatch; triggers re-evaluation (HTTP 409).
- `BudgetExceeded` / `DeadlineExceeded`: Circuit breaker tripped; transitions run to terminal state.
- `ProviderUnavailable`: Transient upstream failure; eligible for bounded backoff retry.
- `ProviderUnknown`: Request timed out; transitioned to asynchronous reconciliation queue.
- `CancelledError`: Propagated immediately to release distributed locks and leases.

## 6. Workflows and Schedulers

### 6.1 Execution Entry Point and Task Claiming

```text
RunService.create(request, identity):
  verify_identity_and_scope(request)
  validate_contract_and_workflow_required_refs(request)
  in Python UoW:
    replay = find_idempotency(principal, operation, goal, key)
    if replay:
      compare_payload_hash_or_conflict()
      return original_receipt
    insert run(status=queued, version_manifest, input_refs)
    insert local dispatch item / inbox linkage
    save idempotency receipt
  return 202 run_ref
```

AMQP consumer writes incoming events directly into the local `Inbox` and `dispatch` tables within a single database transaction before issuing an ACK. Background workers claim tasks using `SELECT ... FOR UPDATE SKIP LOCKED` on the dispatch table, then obtain a distributed lease from Java Core. Stale leases are rejected via CAS fencing.

### 6.2 G1 Bootstrap Graph Node Specifications

| Node | Input $\to$ Output | Conditions & Side Effects |
|---|---|---|
| `authorize` | `input_refs` $\to$ `context_ref` | Aborts if student consent or syllabus version has expired |
| `load_scope` | `context` $\to$ `subgraph/resource_refs` | Read-only access to Java knowledge syllabus; identifies syllabus gaps |
| `deterministic_seed` | `subgraph` $\to$ `candidate_ref` | Topological sort of prerequisites and estimated study hours |
| `propose_plan` | `seed` $\to$ `PlanOutput` | Invokes LA-04 (or deterministic fallback) to generate personalized study path |
| `validate_draft` | `candidate` $\to$ `validation_ref` | Pre-validates draft against student time constraints |
| `persist_draft` | `validated` $\to$ `draft_receipt` | Submits proposal to Java Core via `ProposalPort`; saved as draft, not active |
| `finish` | `receipt` $\to$ terminal state | Awaits student manual confirmation in Java BFF; releases worker process |

### 6.3 G2 Attempt Graph Node Specifications

| Node | Required Inputs | Outputs / Transitions |
|---|---|---|
| `authorize` | `AttemptGraded` event, `input_refs` | Validates grading completion and task authorization; aborts if superseded |
| `extract_features` | Raw behavioral event snapshot | Computes `FeatureRevision` (time, changes, hesitation); records quality flags |
| `analyze` | Grade, features, option mapping | Invokes LA-02; produces diagnosis and misconceptions |
| `explain` | Question, student answer, standard explanation | Invokes LA-03; generates targeted tutoring explanation; submits proposal |
| `personal` | Verified attempt evidence, existing profile | Invokes LA-05; updates knowledge mastery and profile evidence watermark |
| `plan` | Updated evidence watermark, study schedule | Invokes LA-04; recommends review intervals or schedule adjustments |
| `collect` | Branch receipts from Java Core | Evaluates overall cycle status (`completed` / `partial`); writes final receipt |

*Parallel Execution Rule*: `explain` and `personal/plan` execute concurrently. If one branch fails, the other branch's verified receipt remains valid and queryable.

## 7. Five Agent Inner Programs and Model Execution

### 7.1 Unified AgentExecutor Algorithm

```text
execute(invocation, verified_context):
  strict_validate(invocation); ensure_role_registered()
  load_pinned_prompt_policy_model(); assert_scope_deadline_budget()
  inputs = role.load_inputs_via_allowed_tools()
  prepared = role.prepare_deterministic(inputs)
  if role.can_complete_by_rules(prepared):
    return validate_rule_output()
  payload = assemble_trusted_and_untrusted_sections(prepared)
  payload = trim_to_budget_preserving_permissions_versions_facts(payload)
  call_index = allocate_next_logical_call_in_local_transaction()
  persist call_intent(hash, call_index) before any network call
  result = provider_port.reserve_and_submit_or_lookup_same_call(payload)
  if unknown:
    persist unknown; stop automatic new calls; return pending_reconciliation
  parsed = strict_parse_json_and_schema(result)
  if invalid and repair_allowed:
    one_budgeted_new_call_with_error_summary()
  output = role.validate_semantics(parsed, inputs)
  persist output_ref/hash/version; return output
```

### 7.2 Role-Specific Implementations

- **LA-01 Learning Coordinator Agent (`IntentRouterAgent`)**: Deterministic keyword/rule routing first; invokes LLM classifier only for ambiguous user intents; restricts target workflows to authorized catalog; handles clarification loops.
- **LA-02 Attempt Analysis Agent (`AttemptAnalysisAgent`)**: Analyzes grading facts and behavioral hesitation; correlates selected distractors with known misconceptions; never mutates question grades.
- **LA-03 Tutoring Agent (`TutorAgent`)**: Generates targeted pedagogical explanations grounded in RAG evidence; verifies citation provenance; falls back to audited expert explanations if evidence is insufficient.
- **LA-04 Learning Planner Agent (`LearningPlannerAgent`)**: Generates structured study plans and review schedules; validates prerequisite DAGs; enforces student daily study time caps.
- **LA-05 Personal Evidence Agent (`PersonalEvidenceAgent`)**: Gathers objective practice evidence; computes knowledge mastery updates; requires Java Core transaction to commit evidence watermarks.

### 7.3 Model Provider Gateway, Structured Outputs, and Streaming

The `cogniva-model-provider` service acts as an egress proxy:

- Injects provider API keys decrypted from KMS.

## 9. RAG and Pedagogical Algorithms

### 9.1 Retrieval Pipeline Components

1. **ScopeResolver**: Evaluates active course licenses and returns an authorized retrieval filter.
2. **QueryNormalizer**: Expands domain legal terminology while preserving original query intent and temporal scope.
3. **LexicalRetriever**: Executes parameter-bound PostgreSQL full-text search against audited syllabus chunks.
4. **VectorRetriever**: Queries pgvector embeddings within the authorized scope filter.
5. **RankFusion (RRF)**: Combines lexical and dense retrieval rankings using Reciprocal Rank Fusion:
   $$RRF(d) = \sum_{m \in M} \frac{1}{k + r_m(d)}, \quad k = 60$$
6. **EvidenceAssembler**: Validates provenance, token limits, and compiles an immutable `EvidenceSet`.

## 11. Configuration, Runtime, and Delivery

### 11.1 Settings and Environment Matrix

Configuration is managed via Pydantic Settings reading strictly typed environment variables:
- `local`: Containerized PostgreSQL, RabbitMQ, Valkey; `FakeProvider` enabled; mock JWT auth.
- `test`: Isolated ephemeral containers; automated contract and fault-injection suites.
- `stage`: Production-like Kubernetes topology; staging model providers; realistic workload auth.
- `prod`: Encrypted secrets via KMS; strict NetworkPolicies; signed container images; immutable GitOps deployments.

### 11.2 Probes and Graceful Shutdown

- `/health/live`: Liveness probe monitoring internal event loop health.
- `/health/ready`: Readiness probe verifying database connectivity, message queues, and lease availability.
- `/health/startup`: Startup probe validating manifest integrity and dependency warm-up.
- **SIGTERM Sequence**: Sets readiness to false $\to$ ceases task claiming $\to$ awaits bounded in-flight steps $\to$ checkpoints durable progress $\to$ releases distributed leases $\to$ closes connection pools.
