# 4A 关键契约与实施约束 v1.0

日期2026-10-18；依据[需求v0.3](../requirements/通用Agentic学习与考试平台-系统需求规格说明书-v0.3.md)及[4A总体架构](通用Agentic学习与考试平台-4A总体架构设计-v1.0.md)。这是可落地的核心接口/状态设计，完整OpenAPI、JSON Schema、数据库DDL和SDK在E0实施，不宣称已生成或运行。

## 1. 统一上下文与不变量

| 字段 | 作用 |
|---|---|
| principal与role_scope | 服务端认证身份与本次角色，不信任客户端或Agent自报 |
| user_id/goal_id/domain_id/product_id | 确定私人数据、学科和目标作用域；目标所有者再授权 |
| manifest_id/content_revision/policy_bundle | 固定适用内容、答案和学习规则，不用动态latest解释历史 |
| consent_version/entitlement_revision | 数据目的地、费用、权益和自动执行范围 |
| request_id/run_id/parent_run_id | 关联业务与联合任务，不能当业务去重键 |
| expected_revision/idempotency_key | 并发检查与命令去重，按用户/命令/目标限定 |

所有副作用前复核账号/产品/活动/内容撤销状态、授权与预算。当前被停用的内容不因旧检查点仍有引用而继续有效。系统管理员、学科审核者和学生分别具权限；兼任也明确本次角色和审批范围。

## 2. 学习活动与作答

`CreateActivity(goal, task_ref, expected_manifest)`校验内容、能力、权益和目标后产生实例，绑定题目/材料修订、评分规则和披露策略。练习DTO不含未披露答案；重新练习建新实例并保留暴露关系，不覆盖旧作答。

`Submit(activity, answer, expected_revision, idempotency_key)`执行对象授权、活动状态、答案schema、规则纯计算及事务内版本栅栏检查。确定性提交、GradeRevision与Outbox同事务；耗时评价先保存Submission和待评价任务。返回：

```json
{
  "submission_id": "sub_001",
  "persistence_status": "committed",
  "grading_status": "scored",
  "grade_revision": "grade_001_r1",
  "analysis_run_id": "run_001",
  "projection_status": "pending",
  "plan_status": "pending"
}
```

相同键+相同请求返回原结果，相同键不同摘要409；不同键同活动由业务唯一约束仍只接受一次正式提交。跳过、不知道和材料完成是不同事件，不统一编码成普通错答。客户端时间只作参考，服务端received_at为接收事实。

评分修正追加新修订、supersedes及原因，切换有效指针并发出事件，不改原答案。数值评价明确单位、精度、容差、范围并拒绝NaN/Infinity和不支持表达式；不执行用户输入代码。评价失败/无能力返回待处理，不自动造分。

## 3. 个人证据、画像与计划

学习证据引用Submission及GradeRevision、节点/维度、表现、独立性、暴露信息、时间、资格规则和有效状态，具有业务唯一键。资料引用不能作为学习证据，AI分析只作候选归因，正式证据由已审规则决定。

画像返回状态、维度估计、证据充分度、supporting_refs、input_watermark、policy_version、projection_revision和processing_status；未经校准不显示假精确概率。重算写影子代际，再按最新水位及策略CAS切换，旧任务不能覆盖新画像。

计划命令带If-Match或expected_revision，校验目标、资源、先修、权益、画像版本与用户总预算版本；锁定同用户时间周期预算，校验多个目标总和后发布新计划。已完成任务不复活，新增补学显式新任务；用户编辑笔记冲突保留版本，不静默最后写入覆盖。

## 4. 来源检查：失败不是没有变化

| 状态 | 业务含义 | 是否可更新最近成功时间 |
|---|---|---|
| succeeded_changed | 已成功检查且识别到候选变化 | 是，记录修订和变化引用 |
| succeeded_unchanged | 已成功检查且可验证无实质变化 | 是，保留检查依据和来源版本 |
| failed | 超时、解析失败、凭据/网络异常等未完成 | 否，保留失败和升级工单 |
| restricted | 授权、访问条件或政策不允许继续 | 否，暂停相关动作待Owner处理 |
| paused | 按权限主动暂停 | 否，记录操作者和原因 |

SourceRule含来源、关注范围、信任等级、许可、周期、大小/频率/网络限制、Owner与最后状态。Inspection记录开始/结束、成功/失败、原始修订、内容摘要和correlation；原始资料保留原文定位、发布/发现/生效/适用时间，不用网页URL充当完整版本。

去重按来源修订/摘要、业务范围和变化关联，重复可以归并但保留每次发现及失败信息。Scheduler租约和命令唯一键防并发重复检查；没有观察成功时不得刷新last_success_at或发送“知识已最新”的成功提示。

## 5. 变化建议与学科审核

```json
{
  "proposal_id": "prop_001",
  "proposal_revision": 2,
  "domain_id": "legal",
  "product_id": "legal_exam",
  "source_revision": "src_001_r3",
  "baseline_manifest": "release_legal_r1",
  "change_type": "future_rule_change",
  "published_at": "2026-10-18T09:00:00Z",
  "discovered_at": "2026-10-18T15:00:00Z",
  "effective_from": "2027-01-01T00:00:00Z",
  "applicability_status": "needs_subject_review",
  "affected_node_refs": ["legal:node_001"],
  "draft_revision_refs": ["draft_001_r2"],
  "evidence_refs": ["source_passage_001"],
  "suggested_impacts": ["future_relearning"],
  "limitations": ["目标考试适用口径尚待负责人核验"],
  "status": "pending_review"
}
```

变更类别至少区分文字纠错、答案修正、未来规则、结构迁移、授权撤销和新增知识。候选影响不能直接触发所有历史修分。原文、旧母本、新草稿、依据和限制可在工作台对照；AI/提示/分析规则和模型版本留痕，不暴露私有推理链。

`ReviewProposal(id, expected_revision, decision, reasons, approved_scope)`校验学科角色、范围、审批职责及草稿最新修订，decision为accept、accept_with_changes、reject、needs_verification。意见返回原建议；改动导致草稿修订更新时原审批只对其明确版本有效，不能拿旧审批发布新内容。

ReviewDecision保留人工主体、角色、时间、意见、批准内容/适用范围与条件；AI账号和仅system_admin不能调用成功。小团队兼任需具备独立学科授权并按审校政策记录，不能用技术身份伪装专家授权。驳回可归并/关闭并给原因；待核验有Owner、期限和补充后重提入口，不无限循环重发同一建议。

## 6. 发布、撤销与学生影响

`StageRelease`固定待发布内容、规则、许可、学科包、索引代际和人工批准引用；检查每项修订在批准范围内，不存在悬空、失效、未支持活动和未审关键结论。索引与质量检查ready后，`ActivateRelease(expected_active_revision)`原子切换active指针并记录ReleaseActivated事件。

发布失败保留旧可用清单与失败原因，不能先切内容让检索暂用不匹配旧索引。紧急Revoke按权限立即阻断相应新增使用并留原因，回退到已验证清单不抹除已产生事实；恢复前再核对许可、学科和技术条件。

ImpactJob按版本引用定位活动、解释、个人条目和目标，逐项记录：无需影响、仅提示/补学、评分需修正、证据撤销/待验证、画像处理、计划处理、结果可见。历史题按历史口径可能仍然正确，新增未来规则不自动改旧成绩。

作业有游标、租约、重试和人工升级，子项同对象/变更唯一；只有学科决定、发布/无需发布和个人影响处理结果均明确才闭环。通知失败单独重试，外部通知检查发送时授权；站内结果可查，不以“已发通知”替代处理完成。

## 7. Agent协作和RAG资料契约

Handoff包含task_id、parent_run_id、role、scope、manifest/policy版本、input/evidence refs、允许工具、剩余预算和期限、expected_output及幂等标识。接收者重新授权，不能扩大父任务范围。知识发现/分析职责只产候选，讲解不改分，计划建议经业务校验。

Agent任务状态为queued/running/waiting_user/waiting_review/partially_completed/completed/failed/cancelled。等待不占Worker；角色完成不等于正式数据已保存。汇总区分已完成与待处理项、限制及下一步；取消停止后续未开始副作用，已提交事实不撤销成未发生。

EvidencePack是资料集合，含source/revision、定位、类型/信任用途、适用时间、许可/可见性、正文或摘要和限制；生成后校验引用存在、授权、支持关系与评分结论。个人检索和公共检索分别过滤，个人笔记不能提高为权威。检索失败或无依据时返回明确状态及替代，不生成虚构出处。

嵌入、重排、生成分别记录能力和数据目的地授权；变更服务方不得隐式发送个人笔记。多Agent共享父任务预算并限制子层级、总重试、时限，普通规则路由无需额外模型调用；阈值在测试后配置，不写为学科通用常数。

## 8. 事件、幂等和并发

事件封装event_id/type/schema_version、aggregate_id/revision、scope、occurred_at、correlation/causation及安全payload引用。业务事实和Outbox同事务，Dispatcher发布确认后标记，消费者Inbox与业务变更同事务；(consumer,event_id)去重，不能用request_id替代所有业务唯一键。

来源检查、建议、审核和发布有各自聚合版本，跨聚合不保证全局顺序；消费者根据引用和版本回查。重算用输入水位，审核用proposal_revision，发布用active_revision，计划用plan/预算/证据版本，避免单一“最后更新时间”掩盖并发冲突。

外部模型/支付/通知先建Invocation或Delivery及预算/订单引用；未知结果单列对账，无法用数据库事务保证对方恰好执行一次。敏感原文不放队列，任务按权限回查；禁止任意代码对象反序列化。

## 9. 身份、模型、财务与数据请求

模型配置写入不回显密钥，API加密权限与Provider Worker解密身份分离；调用前重新检查账号、内容/数据授权、端点、能力和预算。自配端点逐跳网络校验和独立出网策略，不能让客户端Host或URL绕过SSRF控制。

支付验证签名、时间窗、事件ID、订单、金额币种及可信渠道结果；价格/权益规则保存购买快照，退款有独立记录。模型费用reserved/started/succeeded/failed_known/outcome_unknown/reconciled等状态区分；缓存计数不替代原子预算和账务唯一键。

数据导出/删除请求验证身份并按Owner处理，导出不含他人、密钥或超许可内容；注销先禁用账号、凭据和未开始任务并记tombstone，再处理各类数据，必要保留说明原因。备份恢复先应用删除和禁用账本，防止旧资料通过索引/缓存/检查点复活。

## 10. 接口错误和前台状态

输入非法400，未认证401，授权拒绝403/不可见404，版本/幂等冲突409，能力或业务条件不满足422，限额429，暂不可用503；错误带request_id、code、retryable、user_action和必要安全细节，不返回密钥或内部堆栈。

长任务返回已持久任务ID及可查询状态，SSE或流式订阅按用户再授权并带递增seq，断线后从游标续接，过期返回快照；数据库终态为准，缓存只唤醒。未确认草稿、已保存、已判、讲解失败、画像更新中、来源失败、审核待核验各有不同文案和下一步。

## 11. E0必须补成的机器契约

OpenAPI/DTO/schema、事件与学科包schema、复合外键/唯一键DDL、角色权限矩阵、评分器测试集、Run/Proposal/Release/Impact状态机和错误码清单均在E0生成。验收必须覆盖不同幂等键同提交、审批后改稿、来源失败误判、重复发现、跨目标资料、旧画像覆盖、发布前索引未ready、外部未知费用及恢复后删除重放。本附件给出明确语义，尚不替代实际生成/执行证据。
