# 4A 架构决策与实施门禁 v1.0

日期2026-10-18；状态：推荐设计与实施验证计划。关联[4A总体架构](通用Agentic学习与考试平台-4A总体架构设计-v1.0.md)和[需求v0.3](../requirements/通用Agentic学习与考试平台-系统需求规格说明书-v0.3.md)。用户授权开始设计并更新业务范围；不等于每个框架和阈值已通过评审。旧ADR/手册只作归档，本文件承接当前基线。

## 1. 关键决策

| 决策 | 背景、方案和替代 | 后果与验证／重审 |
|---|---|---|
| AD-01 模块化与进程隔离 | 事务关联强、团队/容量待定；业务模块同库同代码，API、学习、Provider、内容、派生和运营进程独立。全微服务增加协同与事务；单进程会被推理和导入阻塞 | 用依赖检查和数据Owner控制耦合；测混合负载及单池故障。独立发布/容量持续受阻再拆服务 |
| AD-02 关系事实＋检索投影 | 版本/授权/评分需事务，首发有限图可用关系表达；pgvector/词项是派生。专用图/向量/搜索可提供能力但引入同步与运维 | 测中文证据召回、有限图SLO、授权与向量负载；不达标再引入独立读模型，不能假定默认分词足够 |
| AD-03 受控两类Agent群 | 学习和知识运营职责不同；显式任务、角色交接与授权，确定性规则路径无需每次推理。自治聊天群不能保证事实一致 | 测交接、版本、分歧、部分失败、取消和预算。角色增多无收益时合并或规则替代，角色不等于服务部署 |
| AD-04 人机知识运营为P0 | 主动发现、变化分析、学科审核和个人影响是本轮核心；小范围全链先行，不以全网或无人审核替代 | 依赖来源权利及教研产能；测失败不算无变化、待核验、驳回、原稿修订和越权发布。改变人工发布边界先改需求 |
| AD-05 幂等最终一致 | 原始事实短事务、Outbox/Inbox、画像水位、计划CAS，不能拿消息成功当学习完成 | 多状态和补偿是代价；测重复乱序及所有崩溃点。长期补偿复杂到难维护再比较工作流引擎 |
| AD-06 双端共享契约 | Web学习/工作台与App交互不同；共享DTO、API、Token，不强制UI一致。仅Web不能替代总App目标 | 真机、前后台、弱网、公式与读屏测试；App跟Expo兼容React，不强升到Web版本 |
| AD-07 Provider安全身份 | 自配密钥不应在所有Agent/进程解密；API仅加密写入，Provider进程独立解密、网络和预算 | 增加异步交接但有真正IAM边界；测SSRF、密钥扫描、未知费用与撤销。供应方/地域变化重审 |
| AD-08 学科与技术权限分离 | 系统运行权不是学科判断；审校决定和发布版本作用域明确，紧急停用允许独立风险处置 | 兼任要显式学科授权和审校记录；测管理员/Agent自审自发拒绝、技术恢复不重置学科结论 |
| AD-09 支持稳定线而非预发布 | LTS维护和SDK兼容优先，PoC锁具体补丁、镜像摘要和许可；全追最新带来联动风险 | 跟踪维护窗口、CVE与升级，RabbitMQ等短支持线不能长期冻结；Python/Django/DRF/Agent/PG/Expo组合须实际集成 |

## 2. 角色评审与可实施交付

产品确定范围、目标与自动化边界；学科负责人确定来源、适用、评分与证据策略；UI/UE提供三工作入口和全状态；后端/AI/数据提供契约、授权、一致性和迁移；测试提供分层用例、参考集与执行结果；安全/运维提供部署、审计、告警、备份和手册；商业/客服提供费用、权益、退款及支持流程。T项按角色分派姓名、截止日期和决策记录。

完整技术契约在E0形成，前端开发不得自行发明已保存状态；Agent开发不得绕过受控用例直接写画像/费用；内容发布不能仅靠前端按钮权限。跨角色走查以同一源需求、版本和状态为准。

## 3. 阶段门禁

| 阶段 | 核心产物 | 必须通过的检查 |
|---|---|---|
| E0 | 范围、来源/许可、自动化规则、三入口原型、机器契约、依赖锁定和PoC | 双端身份、PG事务、任务去重、Agent恢复、Provider密钥边界、中文检索、人工审批和发布能力 |
| E1 | 法考小范围学习闭环 | 作答与评分事实、解释依据、个人证据画像、计划预算、复习与恢复；原基础AC与RAG/协作适用项 |
| E2 | P0知识运营链 | AC-50～54、57；受控发现、失败/无变化、原文差异、审核修改/驳回、发布、适用性和个人影响 |
| E3 | 通用性、安全和可靠性 | AC-23～32及原适用AC、全部NFR；两实例、双目标、模型兼容、真机、权限、性能与恢复 |
| E4 | 商业首发 | AC-10、22、33及费用/账务门禁；前阶段如收费必须提前，不能推迟对账 |
| E5 | 新学科/媒体/机构等 | 每项新增范围、权利、隐私、安全和独立质量，不自动继承“全部支持” |

不提供未经团队、供应方和内容准备确认的工期承诺。当前状态是设计文档完成，所有真实平台测试均未执行；归档旧报告不能当新门禁证据。

## 4. 质量评估计划

| 类别 | 独立参考与验证 |
|---|---|
| 评分/证据 | 选项真值、数值容差/单位/非有限数、跳过/未知、主次考点归因和复测独立性 |
| RAG/辅导 | 人工标注正确资料、适用时间、引用存在/语义支持、结论、缺证据和恶意材料；不以另一个LLM自评为真值 |
| 多Agent | 正确作用域、交接版本、依赖完成、冲突、部分成功、取消恢复、父子预算和最终业务确认 |
| 知识运营 | 成功检查/失败、有效发现/误报、重复、差异、尚未生效、审核修改/驳回/待核验、发布和个人影响 |
| 画像/计划 | 未见题/延时保持、过度掌握判断、策略变化、双目标总预算、时区及已完成任务不复活 |
| 安全/隐私 | 对象授权、管理/学科职责、SSRF、凭据、富文本、私有检索/缓存、嵌入授权与删除重放 |
| 运维/成本 | API、任务积压、未知费用、对账、分层时延/降级、内容传播、灰度和灾难恢复 |

按学科、难度、版本、争议和场景分层；开发/回归/保留验证集分离，样本和置信限制透明。初始小数据可验证工程流程，不能独立证明99%质量或提分。真实学习效果需要合理试点和对照/基线。

## 5. 运行处置设计

以下是需落成脚本与演练的运行手册，不假定生产资源或命令已存在。共同步骤：确认事件/版本/范围→保护事实与授权→风险隔离/降级→Owner诊断→修复或回退→核对业务与费用→逐步恢复→留痕复盘。

| 手册编号 | 触发与处理重点 | 恢复完成证据 |
|---|---|---|
| RB-01 模型/RAG失败 | 限制故障提供者，保留Run与未知费用，已审内容/允许检索降级；不静默换数据目的地 | 正确引用、已存作答、预算、排队与恢复入口可核对 |
| RB-02 来源检查失败 | 区分失联、解析、限制、无变化；不刷新成功时间；通知来源Owner，人工补录或恢复适配 | 成功记录真实、失败保留、重复候选合并，不自称知识已最新 |
| RB-03 队列与派生积压 | 查Outbox、publisher确认、租约、消费者与死信；不删队列假消警；原ID重放 | 不重复事实/扣费，画像/计划水位推进，毒消息有责任工单 |
| RB-04 重复提交/评分异常 | 回查幂等摘要与活动唯一事实，保护原提交，追加修订而非覆盖 | 成绩、证据及原响应一致，不创建第二次补偿性作答 |
| RB-05 画像/计划错误 | 固定目标/版本/水位，停止错误投影，影子重建、抽检、CAS切换 | 事实不变、跨域无污染、旧Worker不可覆盖，总预算正确 |
| RB-06 未审或错误知识 | 紧急撤销阻断新增使用，学科Owner判类型，审稿/发布/影响处理，许可边界可见 | 原口径、新口径和修分/补学正确，审批与个人结果齐全，不仅已通知 |
| RB-07 提权/密钥事件 | 限制相关角色或调用，撤销/轮换，排查日志/队列/检查点/导出，安全Owner定影响 | 旧密钥不可用、越权路径阻断、学科和私人访问未被管理员身份绕过 |
| RB-08 付款/费用差异 | 查可信渠道、订单快照、唯一事件和Invocation；未知结果保持对账，追加调整项 | 渠道/订单/账务/权益一致，无重复扣费，原任务能续接 |
| RB-09 数据灾难 | 隔离写和外部副作用，确认恢复点，恢复库/对象/身份，先重放删除/禁用，再核对外部交易和重建投影 | RPO/RTO实测、丢失/未知范围、删除保持、无重复副作用，逐流量恢复 |
| RB-10 删除/导出 | 身份核验，按用户/许可过滤，短时导出；禁用凭据和任务、tombstone、在线/索引/检查点/对象处理及例外说明 | 不含密钥/他人数据，备份边界明确，恢复重放不复活已删数据 |
| RB-11 软件/策略/学科包回退 | 识别哪层版本故障、关特性/新活动，回已验版本，旧任务兼容完成或显式迁移，禁止盲目逆DDL | 历史事实、审批、活动、画像和权益可解释，其他学科正常 |

每次演练记录版本、环境、参与者、故障、开始/结束、恢复点、数据与费用核对、删除保持、用户可见状态、残余风险及Owner。管理员仅恢复技术不代表内容审批恢复；跨角色事件必须分别确认各自责任。

## 6. 预算、可用性和发布度量

容量建议100活跃会话与20提交/秒突发，AI并发按预算单独测；每个队列设公平配额与上限，知识导入不能压垮交互。模型等待、检索、各角色和验证均计入整体时延，完整生成/降级分别报告，不以进度替代有用反馈。

可用性按核心非AI、分功能和端到端依赖分别统计，99.9%只是待验证目标；不随意移除内部失败或慢请求。备份/WAL监控支撑RPO，至少季度及重大迁移后恢复演练，保留策略由数据政策确认。费用未知、审批绕过或账务差异任一出现应有事件责任，不能只画大盘。

## 7. 架构变更与当前未知项

新组件需说明对应BA能力、AA边界、DA所有权、TA运行、安全、费用、迁移、回退和验证；没有业务或质量证据不为“企业级”增加基础设施。学科包/来源/提示/模型/策略和价格分别版本化，源需求和四层矩阵同步。

T-01～27保留；首发最低阻断项为内容/来源许可、人工学科Owner、自动化授权、评分与证据基准、提供者数据和费用、部署地区/容量/恢复预算以及首个知识运营全链样例。其余按阶段关闭，不擅自推定用户已经确认所有细节。
