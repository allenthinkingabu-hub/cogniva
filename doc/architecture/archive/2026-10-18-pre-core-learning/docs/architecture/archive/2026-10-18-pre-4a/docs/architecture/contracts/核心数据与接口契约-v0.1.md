# 核心数据与接口契约 v0.1

日期2026-10-18；状态：架构级契约与可执行测试输入的起点，未实现API。[总体架构](../通用Agentic学习与考试平台-总体架构设计-v0.1.md)第8、11～13章为上下文。以下示例ID用于说明关系，不代表已发布内容；完整OpenAPI、JSON Schema及数据库DDL在实现阶段生成并接受本契约约束。

## 1. 服务端上下文

```json
{
  "principal_id": "usr_A",
  "goal_id": "goal_legal_A",
  "domain_id": "legal",
  "product_id": "legal_exam",
  "manifest_id": "release_legal_001",
  "policy_bundle_id": "policy_001",
  "consent_version": 3,
  "request_id": "req_001"
}
```

principal由认证产生；goal必须属于该principal且引用正确产品和清单，不能信任客户端原样传来的上下文。命令携带客户端期望版本，服务端与当前允许版本比较；引用格式相同不代表对象属于同一作用域。所有时间ISO 8601 UTC，日预算另带IANA时区，不用本机时区猜测用户自然日。

## 2. 活动、提交与评分

### 2.1 创建活动

`POST /api/v1/goals/{goal_id}/activities`：输入活动类型、任务引用、期望清单；服务端验证范围、权益、许可、能力和撤销状态，创建`activity_instance_id`并绑定题目/材料修订、评分规则、展示策略和目标。

练习题卡只包含可见题干、选项、资源和作答schema，不含答案、评分映射或预先解析。人工重做创建新的活动实例，保留exposure_count和与旧实例关系，不能用同实例覆盖历史答案。

### 2.2 正式提交

`POST /api/v1/activities/{id}/submission`，必须有`Idempotency-Key`。输入示例：

```json
{
  "activity_revision": "q_001_r3",
  "manifest_id": "release_legal_001",
  "answer": {"selected_option_ids": ["B"]},
  "client_started_at": "2026-10-18T17:00:00Z",
  "client_submitted_at": "2026-10-18T17:02:00Z",
  "self_confidence": null
}
```

服务端记录received_at与validated_duration，客户端耗时只作可疑度和统计参考，不能独立证明学习质量。答案结构按已绑定活动schema校验，限制大小、选项ID、重复项和格式。跳过／不知道用单独学习事件接口，不能编码为空选项并当普通错误答案。学习事件类型包括skipped、declared_unknown、material_started/progressed/completed，按策略决定证据效力。

确定性评分返回201，已提交内容、评分修订和Outbox均在一次事务中提交；耗时评价返回202，已保存Submission和待评价任务。示例：

```json
{
  "request_id": "req_001",
  "submission_id": "sub_001",
  "persistence_status": "committed",
  "grading_status": "scored",
  "grade_revision": "grade_001_r1",
  "result": {"correct": false, "score": "0", "max_score": "1"},
  "analysis_run_id": "run_001",
  "projection_status": "pending",
  "plan_status": "pending"
}
```

业务结果查询包含`GET activities/{id}`和`GET submissions/{id}`，用于重复响应丢失后回查。幂等键按用户＋命令＋目标作用域唯一，保存规范化请求hash；相同请求返回相同业务结果，不保证HTTP状态码始终相同。hash不一致409；同活动实例的不同幂等键也由唯一Submission约束阻止第二次有效提交。

### 2.3 评分修正

GradeRevision包含submission_id、rule_id/version、answer_revision或rubric_version、维度得分、score/max_score、result_status、created_at、supersedes、reason、review_ref。修正追加新修订，不更新旧记录；有效评分指针切换和CorrectionApproved事件同事务。批量修正是可恢复作业，原始作答不变。

## 3. 评价器协议

输入：活动与资源引用、提交、scope、固定规则、资源预算。输出：

```json
{
  "evaluator": {"id": "numeric_decimal", "version": "1.0.0"},
  "submission_id": "sub_math_001",
  "status": "scored",
  "dimensions": [{"id": "calculation", "score": "1", "max_score": "1"}],
  "evidence_eligibility": "policy_required",
  "reason_codes": ["WITHIN_DECLARED_TOLERANCE"],
  "requires_human_review": false,
  "rule_revision": "rule_decimal_r1"
}
```

允许状态scored、needs_review、unsupported、invalid_input、transient_failure；非scored默认不产生强证据。`evidence_eligibility`仅为建议，最终由证据模块按规则决定，评价器不能自授强证据资格。数值配置明确`absolute_tolerance/relative_tolerance/unit/rounding/range`；拒绝NaN/Infinity、超长数值、不支持的表达式和单位冲突；不执行用户代码。

确定性评价需相同输入和规则可复现；开放量表评价保留模型与量表版本、置信限制及人工复核入口，不能宣称LLM评分天然确定。可信内置纯函数可本地执行，外部执行适配以受限进程、最小网络和预算隔离，畸形结果不进入正式评分。

## 4. 学科包清单

```json
{
  "schema_version": "1.0",
  "package_id": "math_foundation",
  "package_version": "1.0.0",
  "product_id": "algebra_topic",
  "mode": "topic_learning",
  "standard_revision": "curriculum_r1",
  "deadline_required": false,
  "capability_dimensions": ["concept", "calculation"],
  "activity_types": ["material_reading", "single_choice", "numeric_answer"],
  "evaluators": ["choice_exact@1", "numeric_decimal@1"],
  "evidence_policy": "math_evidence@1",
  "mastery_policy": "math_mastery@1",
  "review_policy": "math_review@1",
  "source_policy": "reviewed_curriculum@1",
  "update_risk": "standard",
  "content_release": "content_math_r1",
  "supported_media": ["text", "formula"],
  "platform_compatibility": ">=1.0,<2.0",
  "owner_role": "subject_owner",
  "approval_ref": "approval_001"
}
```

配置字段schema有必填、枚举、最大长度与关系约束。引用必须已存在、版本兼容且审核有效；内容授权、能力检测、质量集和全旅程验收通过后才发布。期望能力不等于实际已安装，目录显示已验证能力。manifest固定引用package及内容、策略和索引代际；不得调用`latest`动态重解释历史提交。语义版本和适用时间是两件事。

## 5. 证据、画像与计划并发

Evidence记录submission及grade_revision、node_revision、dimension、结果、自述/事实类型、独立性、暴露信息、occurred_at、effective_status与策略版本。同一评分到同一节点/维度/策略的证据有唯一键；撤销追加状态事件并更新有效指针，保留原因。节点来源不匹配时拒绝写入。

MasteryProjection返回估计与状态、evidence_sufficiency、supporting_refs、as_of、source_watermark、policy_revision、projection_revision、processing_status。未校准时不返回貌似精确的概率confidence。策略新旧比较与重算采用shadow generation，写入时检查最新水位和策略，旧作业不能覆盖新状态。

`PATCH goals/{id}/plan`与个人笔记编辑带`If-Match`；409返回冲突字段和最新revision，不返回别人的内容。计划发布锁定同用户自然日/周期总预算，读取所有活动目标分配；写PlanRevision和任务差异，CAS比较预算/目标/证据版本。原已完成任务引用保持完成，撤销或重新学习显式创建新任务。

## 6. 事件包与消费者

```json
{
  "event_id": "evt_001",
  "event_type": "learning.submission.accepted",
  "schema_version": 1,
  "aggregate_id": "goal_legal_A",
  "aggregate_revision": 42,
  "scope": {"user_id": "usr_A", "goal_id": "goal_legal_A", "product_id": "legal_exam"},
  "occurred_at": "2026-10-18T17:02:01Z",
  "correlation_id": "req_001",
  "causation_id": "cmd_001",
  "payload": {"submission_id": "sub_001", "grade_revision": "grade_001_r1"}
}
```

领域事件清单：submission.accepted、grade.corrected、evidence.changed、mastery.changed、plan.revised、release.activated、content.revoked、product.retired、run.completed、entitlement.changed、account.disabled、data_request.completed。消费者幂等键为consumer_name/event_id，不使用trace_id去重。事件携带引用，敏感原文回查授权用例；consumer按作用域校验后处理。

Dispatcher publisher confirm后标记sent，失败可重试；消费者在业务事务中写Inbox并更新状态，失败回滚。外部副作用先登记Invocation/Delivery记录，再执行，结果未知独立处理；不能以Inbox原子性推断外部收费也恰好一次。死信需有责任和修复后重放方式，不以“进DLQ即完成”结束流程。

## 7. Run、角色交接与流式

Run包含parent_run、role、graph_version、context_ref、input_ref、allowed_tools、status、lease_until、cancel_epoch、deadline、budget_ref、checkpoint_ref和last_event_seq。交接只传允许引用和剩余预算，子角色不能扩大权限。resume时验证用户、当前授权与清单撤销状态，旧授权不因检查点持久化而永久有效。

`GET runs/{id}/events`支持last_seq；所有事件归属同run并再授权；重连返回seq大于游标的记录，过期返回snapshot_required。终态保存在Run表，客户端断网不丢终态。进度和业务引用可持久化，模型原始Token不作为可靠业务事件；最终已验证结果才发布正式解释。流式数据不包含供应方密钥、内部提示或推理链。

## 8. 错误与费用状态

```json
{
  "request_id": "req_001",
  "error": {
    "code": "PROJECTION_NOT_READY",
    "retryable": true,
    "user_action": "查看已保存答案，稍后刷新画像",
    "details": {"submission_id": "sub_001", "last_applied_revision": 41}
  }
}
```

常见业务码：GOAL_SCOPE_MISMATCH、CONTENT_REVOKED、EVALUATOR_UNAVAILABLE、IDEMPOTENCY_CONFLICT、REVISION_CONFLICT、MODEL_CAPABILITY_MISSING、BUDGET_EXCEEDED、PROVIDER_OUTCOME_UNKNOWN、ENTITLEMENT_REQUIRED、CONSENT_REQUIRED。用户错误提示与内部诊断分开。

ModelInvocation状态为reserved、started、succeeded、failed_known、outcome_unknown、reconciled、cancelled_before_start。Invocation由独立Provider Worker按受限身份执行，API只写加密凭据，普通Agent进程不解密；消息仅传Invocation引用，调用前重新校验授权、账号和预算。只有按费用策略确认的事实可结算；业务唯一键为invocation_id＋charge_type＋policy_revision。余额不足不能先扣出负数再异步补偿；超时不能自动释放全部预留并认为供应方未收费。

## 9. 纠错、下架与数据请求

ImpactJob维护对象集合、游标、结果、评分/证据/画像/计划子状态、站内结果引用和人工升级。新版本activate与revocation不混为一类；法律新规则可能只触发未来学习，不必改历史成绩。下架流程阻止新增活动、标记在途任务、提供替代或暂停、核对权益、保留合法历史访问，必须记录每项处理结论。

DataRequest包含申请者、类型、校验状态、对象范围、处理游标、结果、例外理由、导出过期、凭据撤销和备份删除边界。账户禁用与tombstone写入后，异步Worker必须检查并停止生成新个人数据；恢复时先应用删除账本，再开放读写。具体期限在政策确认后填入，不在接口里硬编码法定假设。

## 10. 契约实现验收

至少执行：同键同请求回原结果、同键异请求409、不同键同活动仅一次提交、消息重复乱序、旧画像覆盖阻断、双目标预算并发、评分器NaN/单位/容差边界、流式跨用户续接拒绝、模型未知费用不重复结算、清单撤销即时生效、导出不含密钥。OpenAPI/schema/DDL的实际生成与运行测试属于E0～E3实施产物，本附件不宣称已经生成或上线。
