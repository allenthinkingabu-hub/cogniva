# 运行与恢复手册 v0.1

日期2026-10-18；状态：目标系统的操作设计，尚无生产部署或演练结果。[总体架构](通用Agentic学习与考试平台-总体架构设计-v0.1.md)定义边界。本手册不提供假定存在的生产命令，实施时按实际平台补可执行脚本、权限、资源ID和环境验证。

## 1. 事件响应共同规则

值班人先确认影响和作用域，记录incident_id、开始时间、版本、用户/产品影响、当前操作和Owner；优先保护已提交事实、个人数据和账务。P0越权/泄漏立即阻断受影响路径，其他故障先降级再定位。每次变更记录前后状态，不在未确认环境执行破坏性操作。复盘关联缺陷、测试、需求和ADR。

候选初始阈值见总体17章，正式值按试点锁定。事件响应角色：值班运维协调、模块Owner修复、教研判内容/评分、商业判权益和费用、安全判访问/泄漏、客服统一告知；角色职责不意味着所有人可读所有用户数据。

## 2. RB-01 模型／嵌入／检索故障

触发：提供者超时、限流、引用校验失败激增、队列估计等待超阈值或嵌入服务不可达。

步骤：确认产品、提供者和版本 → 限制受影响调用并保留Run → 展示已审解析或结构化/词项检索 → 记录费用未知调用 → 校验密钥状态、网络、额度与适配兼容 → 修复后用脱敏黄金请求验证 → 小流量恢复。切换模型或嵌入提供者需既有授权，不自动向新服务发送个人资料。

完成证据：提交仍持久、引用和版本正确、未知调用可对账、排队恢复、用户可继续；若证据不足维持降级，不只看HTTP200。关联AC-07、09、17、MAG-03、RAG-04～05。

## 3. RB-02 Outbox／队列／死信积压

触发：最老Outbox或队列超阈值、消费者异常、死信新增。

步骤：区分发布、队列、消费、数据库或业务规则问题 → 不删除Outbox或批量清空队列 → 检查租约、publisher confirms、Inbox冲突及任务版本 → 对毒消息隔离到可追踪工单 → 修复对应消费者或数据 → 以原event_id重放 → 比较事实数量、消费水位和派生结果。

完成证据：重复消费不重复判分/扣费、无序事件能回查补齐、原始事实完整、积压回落、影响工单有结果。关联AC-06、09、11、31。

## 4. RB-03 重复提交／作答保存异常

触发：用户报告重复记录、提交确认后查不到、唯一键冲突激增。

步骤：按request/idempotency/activity查询事实，不信任客户端截图作为唯一账本 → 比较请求hash和原响应引用 → 验证Submission/Grade/Outbox同事务 → 相同活动不创建补偿性第二作答 → 修正响应或状态投影 → 记录原事实及修复原因，必要时冻结受影响接口并保留草稿。

完成证据：同请求回原结果、异请求同键409、不同键同活动不重复、画像证据数与有效提交一致。关联AC-01、06、09、14。

## 5. RB-04 画像／计划错算或延迟

触发：水位落后、旧结果覆盖新结果、跨域状态、总预算超配、用户申诉。

步骤：若跨域先按安全事件隔离 → 固定目标、策略、内容和输入水位 → 暂停错误投影写入，原始作答继续保存 → 在shadow generation重建 → 验证有效评分、证据撤销、独立性与时区预算 → 与旧版比较、抽样教研审核 → CAS切换 → 重排未来任务并展示原因，保留旧快照。

完成证据：事实不变、相同证据可重复重算、旧Worker无法覆盖、计划不超预算，个人影响可见。关联AC-02、04、16、20、26～28、32。

## 6. RB-05 内容紧急撤销／评分修正

触发：答案争议、权利撤销、错误来源、法规或课程规则变化。

步骤：教研/内容Owner确认变更类型 → 紧急风险先更新revocation栅栏，阻止新增分发或评分 → 保留原内容修订审计，不直接删除历史成绩 → 审核新修订并构建索引代际 → 生成影响清单 → 分别执行修分或历史评分不变但需补学 → 撤证、重算和重排 → 站内展示结论，外部通知按偏好 → 核对缓存与签名链接边界。

完成证据：旧新口径明确、所有影响项有处理状态、未决争议有替代、不得仅以“已通知”关闭工单。已下载资料不能保证远程收回，按授权及事件处理说明。关联AC-05、12、17、20、29～31、RAG-01、06。

## 7. RB-06 学科包／评分器／软件回滚

触发：新版本能力不兼容、评分错误、流量异常或核心指标回归。

步骤：关闭受影响新活动/特性 → 保存失败样例与版本 → 判断应用、配置、内容、策略或图哪个版本需回退 → 使用上一已验证清单或镜像 → 检查迁移是否向后兼容，不盲目反向DDL → 在途Run交旧图完成或显式迁移/暂停 → 已产生数据追加修正与重算，不通过回滚镜像抹去事实。

完成证据：原活动和新活动版本可解释，其他产品未被禁用，客户端兼容，费用和画像影响可核对。关联AC-11、23、30～31。

## 8. RB-07 支付、权益与模型费用对账

触发：重复通知、金额不符、权益未到、退款差异、调用outcome_unknown超时。

步骤：查询可信渠道与订单价格快照 → 验签并核对金额/币种/事件ID → 以原业务唯一键重放权益，不再创建新订单 → 模型调用按invocation及提供者request_id查询结果 → 无法确定保持待对账，不自动再调用并重复收费 → 追加账务调整和权益修正，保留原记录 → 让用户回原任务或明确受限入口。

完成证据：订单/渠道/账务/权益一致、无重复结算、退款范围不影响其他产品；成功页面不作为唯一支付证据。关联AC-10、22、33、MAG-04。

## 9. RB-08 凭据泄漏与越权

触发：密钥扫描、异常出网、跨用户/目标访问、提示注入越权成功。

步骤：隔离受影响接口或调用角色 → 撤销/轮换凭据、停止新任务 → 限制出网，保留脱敏审计证据 → 排查日志、队列、检查点、缓存与导出是否含密钥或他人内容 → 安全Owner确定影响及后续告知 → 修复权限/检索/网络边界 → 执行原攻击路径和回归 → 小范围恢复。

完成证据：旧凭据不可用、跨域工具和缓存阻断、泄漏副本处理有记录、无明文密钥进入报告。是否通知及范围依据实际事件和适用规则确定，不由Agent独立决定。关联AC-03、07～08、21、27、MAG-01、RAG-02、05。

## 10. RB-09 数据库灾难恢复

触发：主库不可恢复、故障域损坏或需恢复至历史点。

步骤：停止/隔离写入和外部财务副作用 → 记录最后确认恢复点、WAL水位与事故时刻 → 在隔离资源恢复基础备份和WAL → 验证数据完整性、加密密钥可用和身份库 → **先重放删除/tombstone/账号禁用账本，再开放数据** → 重建可派生索引、缓存和投影 → 对账恢复点后可能缺失的支付、模型及通知事实 → 验证幂等后恢复Dispatcher和Worker → 分流量恢复用户读写。

完成证据：实际RPO和RTO、丢失/不确定范围、账务差异、删除保持、作答和版本完整、恢复后任务不重复扣费。RPO≤5分钟允许灾难恢复有有限数据缺口，不得对外宣称任意灾难零丢失；不能让业务恢复早于删除重放。关联AC-09、11、21、31、RAG-06。

## 11. RB-10 导出、删除与注销

触发：经身份验证的用户数据请求。

步骤：确定范围和政策 → 导出先按用户/目标过滤并排除凭据及他人记录，短时链接交付 → 注销先禁用账号、业务会话、模型配置和未开始任务 → 写tombstone → 按Owner处理在线表、对象、索引、检查点、缓存及可删除日志 → 对必要保留数据脱敏/限制访问并给出理由 → 记录备份过期边界与恢复重放项 → 用户可查结果和例外。

完成证据：导出隔离、凭据停止调用、异步任务不再生成个人内容、合法保留范围和备份期限透明；不能承诺退款自动删除全部数据。关联AC-21、MAG-01、RAG-05～06。

## 12. 演练记录模板与运行验收

每次演练记录：环境、镜像/清单/策略/图版本、参与者、假设、注入故障、开始和结束时刻、恢复点、影响对象、关键查询/指标、数据与费用核对、删除保持、用户可见状态、残余问题、Owner和完成期限。未填写真实结果前只算操作设计，不能标为已通过。

上线最少演练RB-01～06、09～10；正式收费前增加RB-07，安全响应RB-08必须有演练或等价验证。季度和重大迁移后复演数据库恢复、删除重放与关键回滚；每次演练更新自动化脚本和测试集，避免手册与实现分离。
